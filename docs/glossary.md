# Glossary

This page defines the words Bombadil uses for its parts, its screen and its rules, in alphabetical order. A word that means two things has one row for each. Rows for what is on `main` were checked against the code at `a30ebc8` on 2026-10-01. A row that ends with (in progress) describes work built on a branch that is not on `main`, and one that ends with (designed) describes a decided design with no code, so its meaning comes from the brief or page it links. The [roadmap](roadmap.md) says where each piece stands and [decisions](decisions.md) says why it was chosen.

| Term | Meaning | Read more |
| --- | --- | --- |
| `accent` | The Bombadil orange `#d97757`, the colour of the machine acting: the working stone, the pill's border while a turn runs, the primary button and the focus ring. `Theme.tone("accent")` gives it. | [Design system](design-system/README.md#accent-and-status-tones) |
| `after` | A muted line under a system or irreversible step that followed something the turn read from outside, such as "after reading example.com/setup". It states order, not cause. | [Cards and pictures](architecture/cards-and-pictures.md) |
| agentd | The Python daemon that runs one provider CLI turn at a time, takes a restore point first and sends events to every client over one Unix socket. It also answers launcher words itself, with no model. | [agentd](architecture/agentd.md) |
| Alive | The opt-in desk widget for the things being touched at the moment, drawn in the colour of whoever touches them. `src/bombadil/desk.py` registers it as opt-in, and it has no face and no feed (designed). | [Widgets brief](design/widgets-brief.md) |
| aliveness | When and how often a thing was touched, by the person or an agent; it would decide what the brain's map draws at rest. Old things dim and are never removed (designed). | [Brain brief](design/brain-brief.md) |
| app chip | A chip above the pill for each running app: a click slides the app's drawer in or out and the × quits it. The chips are built from Hyprland's windows on workspaces named `special:app-<name>`. | [The shell](architecture/shell.md) |
| app kit | The QML module `Bombadil` and the runtime (`bombadil-app run`, `bombadil-app check`) that turn a folder of QML into a native window that reloads when its files change. | [App kit](architecture/app-kit.md) |
| `app.toml` | The manifest in an app's folder: `title`, `description` and `icon`. | [App kit](architecture/app-kit.md) |
| Ask about this | The Brain window's button that puts `About <path>: ` in the pill (for a page, its address, else its title) and gives it the keyboard, so the person finishes the question. It sends `summon` with `text`. | [The brain](architecture/brain.md), [Brain brief](design/brain-brief.md) |
| Autopilot | The one list of everything that runs on its own, with Pause and Stop on each row. No code for it exists (designed). | [Passenger brief](design/passenger-brief.md), [Principles](principles.md#nothing-runs-unseen) |
| Away | The welcome-back desk widget in the right rail: what finished, who waits, what failed and what changed, with Undo for just that change. `desk.py` registers it, and it has no face and no feed (designed). | [Widgets brief](design/widgets-brief.md) |
| b, the cut | The lowercase b cut through the stone. The stone turns while the b stays level, and the b is drawn in the colour of the surface under the stone so that it reads as a cut. | [Identity brief](design/identity-brief.md), [Design system](design-system/README.md#the-mark-and-its-states) |
| bar | The shell's window on each screen, on the Overlay layer with the namespace `bombadil-bar`. It holds the line, the chips, the stone and the pill, and reserves room at the screen's bottom edge. | [The shell](architecture/shell.md) |
| `because` | The sentence that says why a step happens: the last thing the agent wrote before it, at most 140 characters, kept by `narrate.Narrator`. The status line shows it when hovered or when the step is marked. | [Cards and pictures](architecture/cards-and-pictures.md) |
| `bombadil` | The command-line client in `bin/bombadil`: `ask`, `status`, `stop`, `pill`, `watch`, `history`, `view`, `undo`, `provider`, `signin`, `open` and `brain` (`status`, `why`, `find`, `focus`, `rebuild`). `ask` sends a prompt, which agentd runs as a turn or, for a launcher word, answers without a model. | [agentd](architecture/agentd.md), [The brain](architecture/brain.md) |
| `bombadil view` | The viewer in the details drawer for a file or a command's output: the arrow keys, the wheel and the space bar scroll it, and Esc closes it. | [Cards and pictures](architecture/cards-and-pictures.md) |
| `bombadil-app` | The command that runs an app folder (`bombadil-app run <name>`) or checks it (`bombadil-app check`). | [App kit](architecture/app-kit.md) |
| `bombadil-brain` | `bin/bombadil-brain`, the user service that keeps `brain.db` and answers on `brain.sock`. Its unit is `bombadil-brain.service`, started with the person's session. | [The brain](architecture/brain.md) |
| `bombadil-brain-watch` | `bin/bombadil-brain-watch`, the root service that holds one fanotify mark and sends the user service each write with the writer's process, cgroup and chain of parents. It only collects facts; the user service decides who it was. Its unit is `bombadil-brain-watch.service`. | [The brain](architecture/brain.md) |
| `bombadil-browser` | The command that opens a link: `bin/bombadil-browser` is `$BROWSER` and the http and https handler for `xdg-open`, so any link, including a provider's sign-in page, opens in the browser panel through agentd. The panel's Chromium (its own `--user-data-dir`, the window class `bombadil-browser` and debugging port 9222) is started by `browser.command()` in `src/bombadil/browser.py`. | [Browser and sign-in](architecture/browser-and-signin.md) |
| `bombadil-install` | The installer script on the live system. On `main` it writes a GPT disk with a 1 GiB EFI partition at `/boot` and btrfs subvolumes `@`, `@home` and `@snapshots`, installs GRUB and creates the snapper config `root`. | [ISO and install](architecture/iso-and-install.md) |
| `bombadil-rollback` | The root-only script behind undo: it mounts the btrfs top level, renames `@` to `@.undone-<date>` and snapshots `@snapshots/<n>/snapshot` as `@`. `src/bombadil/snapshots.py` runs it with `sudo`. | [Restore points](architecture/restore-points.md) |
| `bombadil-setup` | The terminal fallback of first boot: it asks which AI should run the computer, installs that provider's CLI if it is missing and signs in. With `--first-run` it exits at once when `~/.config/bombadil/config.toml` exists. | [Browser and sign-in](architecture/browser-and-signin.md) |
| `bombadil-smoke` | A boot-time self-test chosen by the kernel argument `bombadil.smoke`. It prints `PASS` and `FAIL` lines for its checks and powers the machine off; `=install` adds an install to `/dev/vda` and `=undo` an undo round trip over a reboot. | [ISO and install](architecture/iso-and-install.md) |
| `bombadil-vm` | `scripts/bombadil-vm.cmd`, the Windows launcher: it builds the ISO for the checked-out commit and runs it as a VM in a window. `refresh` keeps the VM's disk and takes a restore point first, `stop` shuts it down, `reinstall` wipes the disk after asking, `live` boots the live ISO and `build` only builds. | [ISO and install](architecture/iso-and-install.md#the-windows-launcher) |
| brain | The index of what happened on the machine: things, and the links between them, each with a reason and a time, plus the window that shows it. On `main`: the index `brain.db`, the user service `bombadil-brain`, the root watcher `bombadil-brain-watch`, the Brain window (a built-in app in `share/apps/brain/`), `bombadil brain` (`status`, `why`, `find`, `focus`, `rebuild`) and the pill words `brain` and `why is this here`. The Map, Time and the agents' brain tools are designed. | [The brain](architecture/brain.md), [Brain brief](design/brain-brief.md) |
| `brain.db` | The brain's index: one SQLite file, by default `~/.local/state/bombadil/brain.db`, with the things, the events behind them and the links between them. It is a cache: `bombadil brain rebuild` makes it again from the files, the two attributes and the logs. | [The brain](architecture/brain.md) |
| browser panel | Chromium with its own profile, slid in over the screen as a Hyprland special workspace. Links opened through the system's opener, and the provider's sign-in page, land in it. | [Browser and sign-in](architecture/browser-and-signin.md) |
| built-in app | An app that ships with Bombadil in `share/apps/<name>/` (`apps.builtin_dir`); the Brain is the one on `main`. `bombadil-app run <name>` finds it when `~/Apps/<name>/main.qml` does not exist, so an app of the person's with the same name takes its place. Its folder is read-only, and its saved state lives under `<state>/apps/<name>/data/`. | [App kit](architecture/app-kit.md), [The brain](architecture/brain.md) |
| capsule | The pill's small form under a full-screen window: only the stone and the clock. The desk mode `immersive` turns it on. | [The desk](architecture/desk.md) |
| card | A typed picture the shell draws above the status line from validated data. One card type exists, `diagram`; list, checklist, timer, control and markdown-reader cards are designed. | [Cards and pictures](architecture/cards-and-pictures.md) |
| `CardHost` | `shell/CardHost.qml`, the shell's holder for one card at a time, with a title, a source line, a close button and one sentence. It is loaded so that a failure costs the pictures and never the bar. | [Cards and pictures](architecture/cards-and-pictures.md) |
| checkpoint | A pair of commits saved under `refs/bombadil/<role>/<n>` around each prompt of a coding session, so that a session's undo restores them without touching the branch or the working tree (designed). | [Dev brief](design/dev-brief.md) |
| chip | A small rounded label that stands for one thing. Above the pill it is a queued prompt, a setup choice or a running app; beside the pill it is a desk widget's small face, which is a strip. | [The shell](architecture/shell.md) |
| closing line | The status line after a turn ends: one sentence saying what happened, with Undo and Details buttons when the turn changed something. It is the pill's `closing` mode. | [The shell](architecture/shell.md) |
| coding session | A vendor coding tool or a plain shell that Bombadil hosts in its own systemd scope and shows beside the pill as a dot. The branch that is not on `main` builds the scope and the dot (in progress); running the session as the person without sudo is the fence (designed). | [Coding sessions](architecture/coding-sessions.md), [Dev brief](design/dev-brief.md) |
| colour says who | The rule that white is the person, orange the machine acting, blue a coding session, amber a system step or something waiting on the person, red a failure or what cannot be undone, and green connected. | [Principles](principles.md#colour-says-who), [Design system](design-system/README.md#colour-says-who) |
| `config.toml` | The settings file, read from `/etc/bombadil/config.toml` and then the person's own copy in the config folder. Its keys are `provider`, `model`, `snapshots` and `explain`. | [agentd](architecture/agentd.md) |
| core command | A launcher word that always means the same thing and is checked before app names: `stop`, `undo`, `history`, `hide`, `desk`, `lock`, `restart` and `shutdown` (`CORE_COMMANDS`). | [agentd](architecture/agentd.md) |
| degrade and recover | The rule that every piece degrades and nothing waits on a model it does not need. A card host that cannot draw costs the cards, never the bar. | [Principles](principles.md#degrade-and-recover) |
| desk | The part of the screen around the pill where widgets live: two rails at the sides and strips in the pill's row, with the stage between them left free. `desk` is also the launcher word that folds every card to its strip and back. | [The desk](architecture/desk.md), [Widgets brief](design/widgets-brief.md) |
| desk card | A widget's full face: a 300 px card in a rail, drawn by `NowCard.qml` or `RowsCard.qml` on `DeskCard.qml`. | [The desk](architecture/desk.md) |
| desk mode | `DeskState.mode`, which the widgets brief calls the desk's modes: `open` (nothing in front: full cards), `shared` (a window or panel is in front: the pill narrows to 360 px and covered cards fold) or `immersive` (a full-screen window: the pill becomes a capsule 100 px wide and the desk hides). | [The desk](architecture/desk.md) |
| `desk` tool | The `os-mcp` tool (`show`, `hide`, `move`, `fold`, `unfold`, `state`) that `agentd` lets through only in a turn whose typed words asked for the desk (`desk.asked_for_desk`). | [The desk](architecture/desk.md), [os-mcp](architecture/os-mcp.md) |
| `DeskState` | `shell/DeskState.qml`, the one QML object that decides each widget's face from agentd's events and the window rectangles. It can be tested without a screen, as `PillState` can. | [The desk](architecture/desk.md) |
| `desk.toml` | The desk's saved arrangement in `~/.local/state/bombadil/desk.toml`: which widgets are put away, their rail and order, and whether the desk is folded. It lives in the home folder, which restore points do not cover. | [The desk](architecture/desk.md) |
| desktop test | `tests/desktop/run.sh`: the real bar, agentd and the Claude Code CLI in a headless sway session in Docker, driven by key presses against a scripted API, checking timings, events and pixels. It covers what runs without Hyprland. | [Developing and testing](contributing/development.md#the-desktop-test) |
| Details | The button on the closing line. A click on the closing line itself, on the title of the Now card, or on a picture's box that names a turn does the same: it opens the details drawer. | [The shell](architecture/shell.md), [Cards and pictures](architecture/cards-and-pictures.md) |
| details drawer | A terminal window of class `bombadil-details` on the special workspace `special:details`, opened by Details or by a click on a card's box. It shows `bombadil watch` for a turn, `bombadil history`, or `bombadil view` for a file, a service or a package, and Esc puts it away. | [Cards and pictures](architecture/cards-and-pictures.md), [The shell](architecture/shell.md) |
| `diagram` | The one card type built: boxes and links in one of four shapes (`chain`, `layers`, `compare` or `timeline`), at most 12 boxes and 16 links, laid out by fixed rules and never by a force layout. Each box has a state that sets its colour. | [Cards and pictures](architecture/cards-and-pictures.md) |
| dot | One small indicator per coding session beside the pill: moving while it works, lit when it is the person's turn, red when it failed, dim when asleep (in progress). | [Dev brief](design/dev-brief.md), [Coding sessions](architecture/coding-sessions.md) |
| dot, the pill's mark | In the passenger, identity and UX briefs, the mark at the pill's left end that the stone replaced: "a click on the dot" and "a mark on the dot" mean the stone. Not the coding-session dot. | [Identity brief](design/identity-brief.md), [Passenger brief](design/passenger-brief.md), [UX brief](design/ux-brief.md) |
| drawer | A Hyprland special workspace that slides in over the current one and out again. Each app has its own (`special:app-<name>`), and the browser, terminal, Files and the details drawer use one each. | [App kit](architecture/app-kit.md), [The shell](architecture/shell.md) |
| `Esc` | One of the pill's three keys. While a turn runs it stops the turn; otherwise it clears the typed text, then puts the line, the picture and the drawer away and gives the keyboard back. | [The shell](architecture/shell.md), [Principles](principles.md#stupidly-simple) |
| event | A JSON object `agentd` sends to every client as `{"type": "event", "kind": ...}`. Its `kind` is one of `queued`, `unqueued`, `turn_start`, `status`, `snapshot`, `text`, `tool`, `tool_result`, `file_change`, `output`, `plan`, `card`, `result`, `error`, `turn_end` or `local`. | [agentd](architecture/agentd.md) |
| explain level | `explain` in `config.toml`: `brief`, `normal` (the default) or `teach`. On `main` only `brief` changes behaviour: it leaves out the before-and-after snapshots, so no receipt follows a turn. | [Cards and pictures](architecture/cards-and-pictures.md) |
| face, desk widget | How a widget is drawn: `full` (a card in a rail), `strip` (a chip beside the pill) or hidden. `DeskState` picks the largest face that fits. | [The desk](architecture/desk.md) |
| face, stone | What the stone shows: `starting`, `rest`, `listening`, `working`, `needs`, `done`, `stopped` or `offline`. `PillState.face` gives all but `listening`, which `shell.qml` adds on the screen that holds the keyboard. | [The shell](architecture/shell.md), [Design system](design-system/README.md#the-mark-and-its-states) |
| fake provider | `providers.Fake`, the provider for tests and for running the shell with no AI account: it runs `cat`, so a turn answers `echo: <line>`. `BOMBADIL_PROVIDER=fake` selects it. | [Developing and testing](contributing/development.md#the-fake-provider) |
| fence | What a coding session would run inside: `no-new-privileges` (so no sudo), its own copy, ports and database name, a memory limit, and one door to the machine, `bombadil ask` (designed). | [Dev brief](design/dev-brief.md) |
| finding | One problem that the self-improvement loop found in Bombadil itself, kept by fingerprint (the component, a rule id and the first error line) with its evidence on the machine, so the same problem counts once. One it cannot fix becomes a report that the person may send (in progress). | [Self-improvement brief](design/self-improvement-brief.md#4-finding-its-own-issues), [The loop](architecture/loop.md) |
| first boot | The first start of the image, with no `config.toml`: agentd's setup state is `choose`, and the pill asks which AI should run the computer, then signs in to it. There is no wizard; `bombadil-setup` is the terminal fallback. | [UX flows](ux/flows.md#1-first-boot-and-setup), [Browser and sign-in](architecture/browser-and-signin.md) |
| flash | A local answer drawn over a running turn for 3.5 seconds, or for 8 seconds when it is the reason that `why` gives (`PillState.flash` and `flashFor`). | [The shell](architecture/shell.md) |
| Focus | The Brain window's default view: one thing in the middle with its links in fixed places around it. Where it came from is on the left, what it was read with on the right, what it is used with below and its changes above. | [Brain brief](design/brain-brief.md), [The brain](architecture/brain.md) |
| fold | A desk card's move to its strip within 150 ms of something covering it, and back 400 ms after the cover leaves (`foldMs` and `unfoldDelayMs` in `shell/DeskTheme.js`). `fold` and `unfold` are also operations of the `desk` tool. | [The desk](architecture/desk.md) |
| fuel ring | A thin ring on the stone showing how much of the plan window is used: from 50%, amber from 80%, with an offer to switch at 95% (designed). | [Passenger brief](design/passenger-brief.md) |
| full access | The rule that the agent runs as the person with passwordless sudo and the vendor CLIs in their full-auto modes, and that safety is a restore point instead of a permission prompt. | [Principles](principles.md#full-access-with-undo), [Restore points](architecture/restore-points.md) |
| gate | A root-owned program that would judge a self-made fix: the test that comes with it must fail on the base and pass on the candidate, no protected path may change, and it may touch at most 5 files and 200 lines (designed). | [Self-improvement brief](design/self-improvement-brief.md) |
| generation | A tested tree of Bombadil's own code exported to `~/.local/share/bombadil/gen/<sha>`, with a link `current` at the blessed one and `previous` at its parent, so that undo flips the link (designed). | [Self-improvement brief](design/self-improvement-brief.md) |
| glass | The panel colour at a set opacity for surfaces that float over windows: `glassPill` 94%, `glassLine` 90%, `glassChip` 85%, `glassCard` 96% and `glassStrip` 95%. | [Design system](design-system/README.md#glass) |
| ground | The colour the b is drawn in, which must equal the surface under the stone (`Stone.ground`, by default `glassPill`) so that it reads as a cut. Not the ground colour below. | [Design system](design-system/README.md#the-mark-and-its-states), [The shell](architecture/shell.md) |
| ground colour | The dark base colour `#101214` (`bg`) that the console, the GRUB theme in `share/grub/bombadil/` and Hyprland's desktop background (`background_color` in `hyprland.lua`) share, so that each stage of the start changes the screen once and nothing flashes from black to grey. The b's colour is a different use of the word: see `ground`. | [Boot and wallpaper](design/boot-and-wallpaper.md), [Design system](design-system/README.md) |
| guard | A user service outside every generation that would check for 10 minutes after a self-made change lands and flip back on three failures (designed). | [Self-improvement brief](design/self-improvement-brief.md) |
| history | A launcher word (also `rewind`) and the command `bombadil history`: it opens the recent turns and launcher actions, grouped by day, in the details drawer. | [agentd](architecture/agentd.md), [Cards and pictures](architecture/cards-and-pictures.md) |
| holding card | The card a click on the resting stone would open: what the agent is doing, promised, waiting on and has left unfinished (designed). | [Passenger brief](design/passenger-brief.md) |
| `HyprCover` | `shell/HyprCover.qml`: it polls Hyprland's windows every 300 ms and tells `DeskState` where they are, so that the desk knows what covers the rails. | [The desk](architecture/desk.md) |
| Hyprland | The Wayland compositor Bombadil starts with. Panels and app drawers are its special workspaces, and `agentd` and `os-mcp` drive it over its IPC socket and through `hyprctl dispatch` (`src/bombadil/hypr.py`). | [Foundation choices](design/foundation-choices.md) |
| icon | A Lucide icon in `share/qml/Bombadil/icons/` (77 of them), drawn by the kit's `Icon` component. No other icon set and no emoji belong in the kit. | [Design system](design-system/README.md#iconography) |
| irreversible | A step no restore point can undo, such as `mkfs`, `shred`, `dd` to a device or `rm` in the home folder (`narrate.IRREVERSIBLE`). The status line shows a red edge and the closing line says it cannot be undone. | [Cards and pictures](architecture/cards-and-pictures.md), [Principles](principles.md#full-access-with-undo) |
| job | A background command, a watch on something already running or a timer, started by the `job` tool as a systemd user unit named `bombadil-job-<id>` or, for a timer, `bombadil-timer-<id>`. Its record is kept in `~/.local/state/bombadil/jobs/`. | [The desk](architecture/desk.md), [os-mcp](architecture/os-mcp.md) |
| kit | The `Bombadil` QML module in `share/qml/Bombadil`: 35 entries in its `qmldir`, among them the `Theme` and `Fmt` singletons and components such as `Panel`, `ListRow`, `Meter`, `Diagram`, `Store` and `Editor`. An app uses it with `import Bombadil`. | [App kit](architecture/app-kit.md) |
| kit app | An app built on the kit: a folder in `~/Apps/<name>/` with `main.qml` and, optionally, `app.py`, `app.toml` and `data/`, or a built-in app in `share/apps/<name>/`. It is run by `bombadil-app run <name>`. | [App kit](architecture/app-kit.md) |
| launcher | `src/bombadil/launcher.py`: the exact list of words that agentd answers with no model (`match`) and the `Launcher` that acts on them through Hyprland, the apps, snapper and the brain. Every action returns one plain sentence for the line above the pill. | [agentd](architecture/agentd.md) |
| launcher mirror | The shell page's name for the copy of the launcher's matching rules in `PillState`: `completion(text)` finishes a word on Tab and `exact(text)` says what an exact word would open, before `agentd` answers. | [The shell](architecture/shell.md) |
| launcher word | An exact word typed in the pill that `agentd` handles at once, with no model and no turn: app and panel names, `undo`, `stop`, `history`, `wifi`, `lock`, `brain`, `why is this here` and the like. Anything longer or different goes to the agent. | [agentd](architecture/agentd.md) |
| layout v1 | The installed-OS design's first fixed disk layout: a 1 GiB EFI partition at `/efi`, then LUKS2 over btrfs with the subvolumes `@`, `@home`, `@snapshots`, `@log` and `@pkg` (designed). | [Installed OS brief](design/installed-os-brief.md), [ISO and install](architecture/iso-and-install.md) |
| ledger | The self-improvement design's name for the turn history: `turns.jsonl` with a lasting `id`, start time, seconds, origin, tools, model and cost on every row, so that repeated asks can be counted. A row on `main` has `n` (a turn number that continues across restarts), `started`, `unit` and `files` (`wrote` and `read`), which the brain needs, and none of `id`, `seconds`, `origin`, `tools`, `model` or `cost`. The voice design keeps a separate `said.json` of facts already said (in progress). | [Self-improvement brief](design/self-improvement-brief.md), [Voice brief](design/voice-brief.md) |
| Lifeboat | The rescue for a desktop that has died: a page in large type on tty2 with four one-key choices, and a menu on Super+Ctrl+Backspace while the compositor still runs (designed). | [UX brief](design/ux-brief.md) |
| listening | The stone's lean toward the text. `shell/shell.qml` shows it instead of `rest` on the screen whose pill holds the keyboard. | [The shell](architecture/shell.md) |
| live system | The system as booted from the ISO image before `bombadil-install` has copied it to a disk. It keeps no restore points, so undo starts once Bombadil is installed, and it has no boot record for the boot picture to read. | [ISO and install](architecture/iso-and-install.md#boot-flow) |
| local answer | An answer `agentd` gives without a model, such as a launcher word, a picture word or an ended job. The shell receives a `local` event and the pill's mode becomes `local`. | [agentd](architecture/agentd.md), [The shell](architecture/shell.md) |
| loop | The self-improvement design's cycle in four verbs: Notice the person's repeated asks, Check Bombadil's own state, Mend what it can prove and Tell the project what it cannot fix. Noticing and checking are built on an unmerged branch; mending is designed (in progress). | [Self-improvement brief](design/self-improvement-brief.md), [The loop](architecture/loop.md) |
| Machine | The desk widget that would appear only when memory, disk, processor or heat crosses a line, with meters stacked by who is using them. On `main` `desk.py` registers it with no face and no feed; its card and its sampler exist only on an unmerged branch (in progress). | [Widgets brief](design/widgets-brief.md) |
| Map | The brain's overview: areas laid out once and pinned, bright by aliveness, with bundled roads between them (designed). | [Brain brief](design/brain-brief.md) |
