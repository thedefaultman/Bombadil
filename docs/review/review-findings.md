# Review findings for `claude/first-milestone` (written 2026-09-27 by the foundation thread)

Seven reviewers read the branch at commit "Make the ISO buildable and testable headless" and checked it against the upstream projects it talks to (Claude Code 2.1.283, codex-cli 0.157.1, Hyprland 0.56.2, Quickshell 0.3.1, archiso 90, Qt 6.9, snapper). Each finding then went to two skeptics; the review was stopped before every verdict came in, so each item is marked:

- **confirmed** = both skeptics agreed (several reproduced it against the real binary),
- **confirmed (1)** = one skeptic agreed, the other did not finish,
- **unverified** = the finder's claim only; plausible and specific, but nobody double-checked.

The ISO thread has since fixed some of these on the branch (Lua config, windowrulev2, file_permissions); check the current tree before applying anything below. Line numbers refer to the reviewed commit.

## Blocking on the ISO / demo path

1. **snapshots on the live ISO abort every prompt** — `src/bombadil/snapshots.py:27`, `iso/airootfs/etc/bombadil/config.toml:3` — *unverified (found independently by two reviewers)*. `Snapshots.available` only checks that the `snapper` binary exists; the live root is erofs/overlay with no `root` config, so `sudo snapper -c root create` exits 1, `check=True` raises before `turn_start`, and the prompt is lost. Fix: make `available` check the config (`snapper -c root --no-dbus get-config` returns 0, or `/etc/snapper/configs/root` exists), catch `CalledProcessError` around `snaps.create()` in `agentd.turn` and continue with `snap=None` plus a warning event, ship `snapshots = false` in the live profile and have `bombadil-install` write `snapshots = true` into the installed system.

2. **"undo that" rolls back to the snapshot of the undo turn itself** — `src/bombadil/snapshots.py:56` — *unverified, but reproduced by the finder*. agentd snapshots before every turn, including the undo turn, so `undo_last_turn()` picks the newest `turn:` snapshot = the state after the change. Fix: pass the current turn's snapshot number to the MCP server (e.g. `env BOMBADIL_TURN_SNAPSHOT=<n>` on the provider subprocess) and have `undo_last_turn` skip snapshots with `number >= that`; update `test_snapshot_and_undo` (two turn snapshots, current = 2, expect rollback to 1).

3. **`snapper rollback` is a no-op with `subvol=@` in fstab** — `src/bombadil/snapshots.py:52`, `bombadil-install:16,22` — *unverified*. snapper's rollback only changes the btrfs default subvolume; an explicit `subvol=` mount option overrides it, so the machine boots the unchanged `@` again. Fix: either the SUSE layout (root mounted without `subvol=`, `.snapshots` under `@`, `btrfs subvolume set-default`) or implement rollback the snapper-rollback way (mount `subvolid=5`, move `@` aside, snapshot `@/.snapshots/N/snapshot` to `@`). Add a smoke check that a rollback actually changes `/`. (Memory says the ISO thread's `MODE=install` test does "undo across reboot"; if that passes, this is already handled.)

4. **`snapper create-config` fails inside the installer** — `bombadil-install:34` — *unverified*. `/mnt/.snapshots` is mounted before the chroot, so `create-config /` hits EEXIST and `|| true` hides it: no config on the installed system, every turn errors. Fix: before `arch-chroot`, `umount /mnt/.snapshots && rmdir /mnt/.snapshots`; in the chroot `create-config /` (no `|| true`), then `btrfs subvolume delete /.snapshots && mkdir /.snapshots && chmod 750 /.snapshots`; after the chroot remount `subvol=@snapshots` (fstab already has the line). Optionally `ALLOW_USERS="user"` in the config.

5. **`cp` argument collision aborts `bombadil-install`** — `bombadil-install:23` — *unverified, reproduced with coreutils 9.4*. `cp -a /etc/greetd /etc/sudoers.d/bombadil /etc/bombadil /mnt/etc/` puts the sudoers *file* at `/mnt/etc/bombadil`, then fails on the directory of the same name; `set -e` kills the installer after pacstrap. Fix: `cp -a /etc/greetd /etc/bombadil /mnt/etc/` and `install -d -m 750 /mnt/etc/sudoers.d && install -m 440 /etc/sudoers.d/bombadil /mnt/etc/sudoers.d/bombadil`.

6. **`sgdisk` is not on the ISO** — `iso/packages.x86_64` — *unverified*. Nothing pulls in `gptfdisk`; the installer dies at its first command. Add `gptfdisk` and `dosfstools` (the latter only comes via archinstall, which the installer filters out of pacstrap).

7. **exec bits stripped from `/usr/share/bombadil/bin/`** — `iso/profiledef.sh` — *unverified; memory says the ISO thread already hit and fixed this*. mkarchiso copies airootfs with `--no-preserve=mode`; add `["/usr/share/bombadil/bin/"]="0:0:755"` (trailing slash = recursive).

8. **Hyprland config** — `hyprland.conf:19,33,45-47` — *confirmed*. `windowrulev2` is a hard error in 0.53+; one-line `{ a = 1; b = 2 }` blocks are not hyprlang (`;` is not a separator; a category opens only on a line ending in `{`), so blur/input settings are silently dropped with two more errors. Memory says the ISO thread moved to the Lua config, which supersedes this; if any hyprlang config remains, use the block form `windowrule { name = ...; match:class = ...; float = on; center = on; size = 540 660 }` and multi-line `blur {}` / `input {}`.

9. **generated apps need their own class prefix** — `src/bombadil/app_runtime.py:21`, `apps.py:63` — *confirmed as part of #8*. The window rule must not match the panel apps (`bombadil-browser`, `bombadil-terminal`, `bombadil-setup`), and RE2 has no negative lookahead. Fix: `setDesktopFileName(f"bombadil-app-{app.name}")`, desktop entry `bombadil-app-{name}.desktop`, rule `match:class ^(bombadil-app-.*)$`, test expects the new file name.

10. **the bar cannot be typed into** — `shell/shell.qml:55` — *unverified*. A layer-shell PanelWindow defaults to `KeyboardFocus.None`. Add `WlrLayershell.keyboardFocus: WlrKeyboardFocus.OnDemand` (or `focusable: true`) next to the `WlrLayershell.layer` line; not `Exclusive`, which would lock apps out of the keyboard.

11. **the bar never reconnects after a failed first connect** — `shell/shell.qml:38` — *unverified*. Quickshell's `Socket` emits `connectionStateChanged` only on connect/drop, not on a failed attempt; on first boot agentd starts after the bar (and exits until the provider is installed). Add `onError: reconnect.restart()`; if the packaged Quickshell predates quickshell-mirror#1181, recreate the Socket per retry via a `Loader`.

12. **Theme is not registered as a singleton** — `share/qml/Bombadil/qmldir:2` — *unverified, but this is plain Qt doc*. Change to `singleton Theme 1.0 Theme.qml`; otherwise every `Theme.*` is undefined and generated apps open white with default fonts.

13. **the smoke test's screenshot check lacks WAYLAND_DISPLAY** — `bombadil-smoke` — *unverified*. Hyprland's socket is `wayland-1`, grim defaults to `wayland-0`. Set `WAYLAND_DISPLAY=$(basename /run/user/<uid>/wayland-1)` (or glob) in that check.

## Confirmed defects in the provider adapters (both providers)

14. **nothing streams to the bar** — `src/bombadil/agentd.py:122` — *confirmed, reproduced*. `turn()` buffers all of stdout until the CLI exits, so the bar shows only the pulsing dot for the whole turn. Also stderr is not drained concurrently (deadlock past ~256 KiB), and the default 64 KiB `StreamReader` line limit raises `ValueError` on a stream-json line carrying a base64 screenshot, which kills the turn without `turn_end` (so `bombadil ask` hangs). Fix, all three: `create_subprocess_exec(..., limit=64*1024*1024)`; `stderr_task = asyncio.create_task(proc.stderr.read())` before the loop; parse and broadcast per line (`for ev in provider.events(line)`), with the loop in `try/finally` so `turn_end` is always sent and the child killed on a parse error; make `Provider.events` take one line (Claude/Codex are already stateless per line; `Fake.events` yields on the single chunk `cat` returns). Add a test with a stub CLI that sleeps between lines and asserts the first `text` arrives before exit, and one with a >64 KiB line.

15. **prompt is a positional after `-p` / last arg of `codex exec`** — `providers.py:67,115` — *confirmed on both binaries*. A prompt starting with `-` is parsed as options (`-rf ...` becomes `--resume`, `-h` prints help and the turn ends silently; clap rejects `-5 degrees outside`). Best fix: send the prompt on stdin for both (Claude Code documents `-p` reading stdin; codex reads it when no positional is given; agentd already has the stdin pipe and writes it for Fake), via a `Provider.prompt_on_stdin` flag replacing the `name == "fake"` special case. Smaller fix: options first, then `["--", prompt]` (Claude) and `["--", session_id, prompt]` (Codex resume); note a bare `claude` subcommand name typed as the prompt ("update", "doctor") still dispatches even after `--`, which is why stdin is better.

16. **error results lose their reason** — `providers.py:95`, `agentd.py:136` — *confirmed*. On `is_error` results the CLI omits `result` and puts the reason in `errors: [...]`, which the parser never reads; a cancel (SIGINT) exits 0 with empty stderr, so the user sees nothing. Fix: in `Claude.events` result branch, `text = m.get("result") or "\n".join(str(e) or e.get("message") ...)`, pass through `subtype` and `terminal_reason`; in agentd, when `not ev["ok"]` broadcast an `error` event ("cancelled" when `terminal_reason` starts with `aborted`), and gate the stderr fallback on "no error already reported" rather than `not result_text`; record `ok` in turns.jsonl.

17. **a dead `--resume` id wedges agentd forever** — `agentd.py:132` — *confirmed*. When the transcript is gone (30-day sweep, `claude project purge`), the CLI returns `is_error, num_turns: 0, session_id: <bad id>` with no init event; agentd adopts it from every result and never clears it. Fix: adopt `session_id` only from `ok` results; when a resumed turn fails with `num_turns == 0` (or `errors` contains "No conversation found") set `self.session_id = None` and broadcast "previous session is gone; starting a new one". Do **not** reset on missing `num_turns` alone: Codex/Fake results carry neither field and would lose their id.

18. **MCP server failure is invisible** — `providers.py:85` — *confirmed*. `system/init` carries `mcp_servers: [{name, status}]`; a failed `bombadil-os` still yields a `success` result. Yield an `error` event when the `bombadil-os` entry is missing or its status is not `connected`/`pending`, and for `mcp_server_errors` entries. Optional: fail fast in `agentd.main()` if `mcp_command` is not executable.

19. **Codex `-c instructions=...` replaces Codex's whole system prompt** — `providers.py:109` — *confirmed, reproduced*. `instructions` is "reserved for future use" and acts as a replacement; use `-c developer_instructions=<json.dumps(SYSTEM_PROMPT)>` (appends). Any Codex session id saved before this fix must be discarded, not resumed.

20. **Codex resume drops every override** — `providers.py:113` — *confirmed, reproduced*. The resume form omits `-c mcp_servers...`, the instructions, `--skip-git-repo-check` and `--model`, so from turn 2 Codex has no OS tools. Build the overrides once and use them in both forms; `codex exec resume` accepts `-c`, `-m`, `--json`, `--dangerously-bypass-approvals-and-sandbox`, `--skip-git-repo-check`, but **not** `-C` (agentd already sets cwd).

21. **Codex starts the MCP server with a whitelisted environment** — `providers.py:108` — *confirmed, reproduced*. Only HOME/PATH/SHELL/TERM/PWD reach `bombadil-os-mcp`, so under Codex `show_panel` raises "Hyprland is not running", grim/notify/`bombadil-app` have no Wayland/D-Bus. Add `-c mcp_servers.bombadil-os.env_vars=<json list>` forwarding `HYPRLAND_INSTANCE_SIGNATURE, XDG_RUNTIME_DIR, WAYLAND_DISPLAY, DISPLAY, DBUS_SESSION_BUS_ADDRESS, XDG_CONFIG_HOME, XDG_STATE_HOME, XDG_DATA_HOME, XDG_SESSION_TYPE, BOMBADIL_*` (unset names are skipped harmlessly), on both command forms.

22. **Codex event parsing** — `providers.py:133` — *confirmed*. `turn.failed` (the only real failure signal) is ignored; top-level `error` events are retry notices ("Reconnecting... 2/5") shown as failures; `turn.completed` carries only `usage`, so the result text is always empty. Fix: remember the last `agent_message` text and emit it in the `turn.completed` result; on `turn.failed` yield an `error` and a `result` with `ok: False`; emit top-level `error` as an informational `text`, never as `kind: error`. Do not string-match "Reconnecting".

23. **`--dangerously-skip-permissions` is refused as root** — `providers.py:69` — *one skeptic refuted as "not a defect"*: every shipped path runs as `user`, and the per-turn error already carries the CLI's message. If wanted, add `Provider.preflight()` returning a message when uid 0 and `IS_SANDBOX` is unset, checked in `agentd.main()`. Note the docs now name `claude auth login` as the login command; `bombadil-setup` uses `claude /login`.

## Other confirmed or likely defects

24. **`show_panel` relaunches while the app is still starting** — `src/bombadil/hypr.py:62` — *confirmed (1), consequence corrected*. A second call before Chromium maps re-execs; the duplicate lands inside the panel (not outside, as first claimed), and `panel()` returns "shown" instantly, which invites the agent's retry. Fix: after `dispatch exec`, poll `clients()` every 0.2 s up to ~20 s for a client on `special:<name>`; on timeout return "launched, still starting"; before exec, treat `pgrep -f -- '--class=bombadil-browser'` (etc.) as already launched. Do **not** give Chromium a per-panel `--user-data-dir` (breaks the shared CDP port 9222).

25. **`rollback` lets snapper print onto the MCP stdout transport** — `mcp_server.py:103`, `snapshots.py:52` — *unverified*. `rollback()` runs without `capture_output`, so snapper's progress lines corrupt the JSON-RPC stream (the Claude SDK throws on non-JSON lines). Fix: `capture_output=True` there, and in `mcp_server.main()` dup the real stdout to a private fd, point fd 1 at stderr, and serve on the private fd so no child or stray print can touch the transport.

26. **`bombadil ask` returns on whichever turn ends first** — `bin/bombadil:23` — *unverified, reproduced by the finder*. Events are broadcast to all clients; `talk()` prints another client's turn and exits at the first `turn_end`; an empty prompt blocks forever; a missing daemon tracebacks. Fix: agentd assigns a turn id on enqueue, replies `{"type":"queued","id":n}`, tags events with `"turn": n`; `talk()` filters on its id; reject empty prompts; catch `OSError` on connect.

27. **`app.py` is never reloaded** — `src/bombadil/app_runtime.py:41`, `mcp_server.py:65` — *unverified*. `Backend` loads once; `create_app` refuses to restart a running app, so a second call that changes the Python runs new QML against the stale backend. Fix: on an `app.py` change re-exec the process (`os.execv(sys.executable, [sys.executable, *sys.argv])`), or have `create_app` terminate and relaunch when `python` is given; say so in the tool description.

28. **reload destroys the window before the new QML compiles, and errors are discarded** — `app_runtime.py:42`, `apps.py:90` — *unverified*. On a QML error the old root is already deleted and stderr goes to `/dev/null`, so the agent is told "opened" and sees nothing. Fix: compile with `QQmlComponent` first, keep the old root on error, write errors to `state_dir/apps/<name>.log`, have `apps.run()` log there instead of DEVNULL, and have `create_app`/`open_app` wait ~1 s and return the log tail on failure.

29. **`Bombadil.Window` shadows `QtQuick.Window`** — `share/qml/Bombadil/qmldir:3` — *unverified*. Works only when `import Bombadil` comes after `import QtQuick`; an agent that orders them differently gets "Cannot assign to non-existent property subtitle". Rename to `AppWindow` (file, template, tool description, `test_mcp_server` template check).

30. **font family "Inter, sans-serif" is one literal name in Qt 6** — `Theme.qml:12` — *unverified*. Use `family: "Inter"`; add fallbacks via `QFont.insertSubstitution` in Python if wanted.

31. **QML import path ignores `BOMBADIL_SHARE` and the `/usr/share/bombadil/qml` fallback never exists** — `app_runtime.py:33` — *unverified*. Use `paths.share_dir() / "qml"` (the ISO tree lives at `/usr/share/bombadil/share/qml`).

32. **Quickshell nits** — `shell/shell.qml` — *unverified*: the clock `Timer` uses `parent.text` (Timer has no `parent`; give the Text an id); the `MouseArea` at `z: -1` under the `Flickable` never gets the click (use `TapHandler { onTapped: fade.stop() }`); the reply box sets `visible` from the transcript so the opacity fade is never seen (drive `visible: opacity > 0`).

33. **greetd should launch `start-hyprland`** — `iso/airootfs/etc/greetd/config.toml` — *unverified*. Since 0.53 the wrapper provides crash recovery / safe mode; direct launch logs a warning. Set `command = "start-hyprland"` for both sessions.

34. **`apps.create` writes `app.toml` without escaping** — `apps.py` — *reviewer note, unverified*. A `"` or newline in a title breaks `tomllib` for every later `list_apps`. Escape with `json.dumps(title)` (valid TOML basic string).

## Checked and found correct

Claude Code flags and stream-json shapes (`-p`, `--output-format stream-json`, `--verbose`, `--permission-mode bypassPermissions`, `--dangerously-skip-permissions`, `--mcp-config` with `{mcpServers:{...}}` and no extra allow-list flags needed in `-p` mode, `--append-system-prompt`, `--model`, `--resume`; MCP tools auto-approved under bypass); Codex `exec` flags and event names; Hyprland IPC socket path, `dispatch` form, `j/clients`/`j/monitors` shapes, `[workspace special:x silent]` exec rule, `togglespecialworkspace` taking the bare name, animation names; Quickshell `ShellRoot`/`Variants`/`PanelWindow`/`WlrLayershell.layer`/`Socket`/`SplitParser`/`Quickshell.env`/`pragma UseQApplication`; all package names in `packages.x86_64` exist in extra; `snapper --jsonout list` shape, `create --print-number`, `rollback [N]`; the MCP server's protocol handling; `pgrep` pattern in `_is_running`; PySide6 `Property`/`Slot`/`Signal` usage; `QFileSystemWatcher` re-add pattern; `setDesktopFileName` → Wayland app_id.
