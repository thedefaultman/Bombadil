You can fork Bombadil and change almost everything about how it looks and what it does: the mark, the colours, the wording, the wallpaper, the name, the default AI, the tools the agent has, the pictures and widgets the shell draws, the apps that ship and the packages on the image. What makes it Bombadil is a short list of rules ([principles](principles.md)) and the few files that enforce them. This page says which is which. The first table lists where the identity lives and what to keep in each place, the second section lists the rules a fork inherits, and the recipes say, for eleven common changes, which files to edit and which tests to run.

## Get it running

All four start from a clone of your fork. The Python parts need Python 3.11 or newer and no runtime packages, except `httpx` and `mcp`, which the connection service imports for a connection on its real engine (its fake engine needs neither).

| You want | Commands | Needs |
|---|---|---|
| The test suite | `python3 -m pip install -e '.[dev,apps]'`, then `python3 -m pip install cryptography pillow numpy cairosvg httpx mcp`, then `pytest` | `dev` brings `pytest`, `pytest-asyncio` and `ruff`; `apps` brings `PySide6`. `cryptography`, the picture packages, `httpx` and `mcp` are not declared in `pyproject.toml`; `tests/test_connect_slack.py` imports `httpx` and `tests/test_connect_mcp.py` imports `httpx2`, which `mcp` brings. |
| A session with the echo provider, no desktop | `BOMBADIL_PROVIDER=fake bin/agentd &`, then `bin/bombadil ask "hello"` | Nothing else. The reply is `echo: hello`. |
| The bar on a desktop you already have | `scripts/dev-session.sh` (the echo provider), or `BOMBADIL_PROVIDER=claude scripts/dev-session.sh` | Hyprland and `quickshell`, plus `pyside6` to create apps. The script also starts the mail service and the connection service on their fake engines, with sample mailboxes and sample messages and tasks in scratch folders; `BOMBADIL_CONNECT_ENGINE` set to anything but `fake` leaves the connections to the system unit. |
| The image | `scripts/build-iso.sh`, or `scripts/build-in-container.sh` with Docker or Podman, then `scripts/run-vm.sh` | An Arch host with `archiso`, or a container; QEMU and OVMF to boot it. |

The suite is large. On 2026-11-09, `pytest --collect-only -q` at `ca7f80a` counted 3,636 tests in an environment with `pytest-asyncio` and without `PySide6`, so the QML test modules, which skip themselves without it, were not among them. The count at `24c836c` is in [Run the tests](contributing/development.md#run-the-tests). Run one file while you work and the whole suite before you push; how long the whole run takes was not measured for this page. Without `PySide6` the QML tests skip, and the two wallpaper tests that draw the picture again skip without `pillow`, `numpy` and `cairosvg`. Without `pytest-asyncio` the async tests fail with "async def functions are not natively supported". The image build, the VM smoke, the QML tests and `bombadil-app check` were not run for this page.

The session above uses your real state, config and socket folders. [Developing and testing Bombadil](contributing/development.md#run-a-dev-session-against-a-checkout) shows how to point them at a scratch folder, and covers the other test layers, the `BOMBADIL_*` variables and the VM tools.

## What to keep (the rules a fork inherits)

Each rule is one heading in [principles](principles.md), with the brief that decided it. A change that breaks one turns Bombadil into a chatbot with a desktop around it, or a desktop with a chat sidebar.

| Rule | In one line |
|---|---|
| [The person is a passenger](principles.md#the-person-is-a-passenger) | The AI is the interface, and the person can see the road. |
| [Full access with undo](principles.md#full-access-with-undo) | Full access, with a restore point before every turn (on an installed system) instead of a permission prompt. |
| [Real native apps](principles.md#real-native-apps) | What the agent makes is a native app, never a web page on a port. |
| [One machine one conversation](principles.md#one-machine-one-conversation) | One conversation and one memory the person can read, not a list of chats. |
| [Recovery without the broken part](principles.md#recovery-without-the-broken-part) | Stop, undo and rescue never go through the part that broke. |
| [Records before models](principles.md#records-before-models) | Records answer before models do, and the machine explains itself from what it kept. |
| [The person's press reaches people](principles.md#the-persons-press-reaches-people) | Only the person's own press reaches other people or leaves the machine. |
| [Nothing runs unseen](principles.md#nothing-runs-unseen) | Nothing runs on its own that the person cannot see and stop. |
| [Plain files stay the truth](principles.md#plain-files-stay-the-truth) | Folders are still folders, and the person's home is never rewritten. |
| [Stupidly simple](principles.md#stupidly-simple) | One pill and three things to learn. |
| [Something true in 200 ms](principles.md#something-true-in-200-ms) | Something true is on screen within 200 ms of Enter, and open, stop and undo never wait for the model. |
| [The answer is the thing](principles.md#the-answer-is-the-thing) | A window, a card or a panel appears; written replies stay short. |
| ["This" means what you see](principles.md#this-means-what-you-see) | "This" means what is in front of the person. |
| [Quiet at rest](principles.md#quiet-at-rest) | At rest the screen is wallpaper and one pill, and every movement means one thing. |
| [Colour says who](principles.md#colour-says-who) | White is the person, orange is the machine acting, blue is a coding session. |
| [One design language](principles.md#one-design-language) | The shell and every app read the same tokens, kit and plain voice. |
| [Original](principles.md#original) | Nothing borrowed, no face and no mascot. |
| [Degrade and recover](principles.md#degrade-and-recover) | Every piece degrades, and nothing waits on a model it does not need. |

### The six that break the product soonest

1. **[Full access with undo](principles.md#full-access-with-undo).** The agent runs with the CLIs' no-prompt flags (`src/bombadil/providers.py:267`, `:590-592`) and its only safety is the restore point taken before each turn, which exists only where `snapper` has a `root` configuration (`src/bombadil/snapshots.py:32-34`), so a fork that leaves btrfs or turns snapshots off keeps the power and loses the way back. The installed system takes no hourly restore points and keeps the newest 30 (`bombadil-install:70-72`; `NUMBER_LIMIT=30` is the number to change), so an undo reaches back 30 restore points and no further. The 30 applies only to restore points that `Snapshots.create` makes with `--cleanup-algorithm number` (`snapshots.py:43-46`): one made without it is never deleted. `tests/test_snapshots.py:16` pins the argument, `tests/test_iso_profile.py:150` the installer's `set-config` line, and the installed-disk smoke checks `snapshot-is-prunable` and `snapshots-are-pruned` (`bombadil-smoke:652-653`).
2. **[Recovery without the broken part](principles.md#recovery-without-the-broken-part).** `iso/airootfs/etc/skel/.config/hypr/hyprland.lua:75` binds `bombadil stop`, `:77` restarts the bar with `systemctl --user restart bombadil-shell`, and `bin/bombadil:434` runs `undo`, none of them through the shell or a model, so a fork that moves them into the pill leaves the person stuck on the day the agent breaks the shell.
3. **[The person's press reaches people](principles.md#the-persons-press-reaches-people).** None of the 31 tools of `bombadil-os-mcp` sends, posts, creates, comments, pays or pushes (`src/bombadil/mcp_server.py:56-182`; the five `mail_*` tools read, mark and draft, `src/bombadil/mail/tools.py:67`, and the five connection tools read messages and tasks and put a draft on a card, `src/bombadil/connect/tools.py:87`), because the agent reads other people's words and undo cannot take back a message, so a fork that adds such a tool moves the press from the person to a model. `tests/test_mcp_server.py:410` (`test_the_mail_tools_are_listed_and_there_is_no_way_to_send`) fails a tool with `send` in its name and any `mail_*` tool beyond the five, and `tests/test_mcp_server.py:490-499` (`test_the_five_connection_tools_are_listed_and_none_of_them_sends`) a connection tool whose name sends or whose inputs take a token, a fingerprint or a connection. What leaves is the person's press on a card's button, and it is held twice: `agentd` refuses a press from a process in the scope of a turn or of a coding session (`src/bombadil/outbox.py:274-284`), and the connection service, which keeps the keys to Slack and the work tools as a system user of its own in a folder of mode 0700, refuses it again and works the fingerprint of the words out again (`src/bombadil/connect/service.py:992-1000`). A fork keeps both refusals, the fingerprint and that folder; the image's passwordless `sudo` still lets the agent's own shell read it, so against the agent that folder is a rule with a check and not a wall ([the connection service](security-model.md#the-connection-service)).
4. **[Nothing runs unseen](principles.md#nothing-runs-unseen).** A background job is a transient systemd user unit made by the `job` tool, which the desk's Watching card lists and the person can stop (`src/bombadil/mcp_server.py:151-170`, `src/bombadil/jobs.py:162`), so a tool that starts a daemon of its own makes work nobody can see or stop.
5. **[Something true in 200 ms](principles.md#something-true-in-200-ms).** `src/bombadil/launcher.py` answers open, close, stop, undo, the desk, the volume words, `use opus` and `use sonnet`, and the picture words inside `agentd` with no model (`launcher.py:1-16`; `CORE_COMMANDS` at `:49`, `UTILITY_COMMANDS` at `:85`, `PICTURE_PHRASES` at `:120`), so a fork that sends them to the provider makes every first answer as slow as a model.
6. **[One design language](principles.md#one-design-language).** The shell reads `Theme.qml`, and `tests/test_theme.py` fails a hex colour or a `Text` with no font family in `shell/*.qml`, so a fork that styles one widget by hand fails the suite and stops matching the apps the agent writes.

## Common changes

### 1. Add a provider

A provider is one CLI that the daemon starts for each turn. Details: [agentd](architecture/agentd.md#add-a-provider).

1. In `src/bombadil/providers.py`, subclass `Provider` (`:89`). Set `name`, `title`, `binary` and `signin_host`, and write `command(turn, workdir)` and `parse(line)`. `Claude` (`:257`) and `Codex` (`:564`) are the two worked examples.

   ```python
   class Acme(Provider):
       name = "acme"
       title = "Acme"
       binary = "acme"
       signin_host = ("auth.example.com", 443)

       def command(self, turn: Turn, workdir: Path) -> list[str]: ...
       def parse(self, line): ...
   ```

2. `command` must give the CLI the system prompt (`system_prompt()`, as `:266` and `:575` do), the `bombadil-os` MCP server (`mcp_config()` at `:77` writes Claude's file; Codex takes `-c mcp_servers.bombadil-os...` overrides at `:573-574`) and its own full-access flag (`:261`, `:584-586`), so every provider has the same powers ([security model](security-model.md#if-you-fork-it)).
3. `parse` yields the events `agentd` reads. `session`, `text`, `thinking`, `tool`, `tool_result`, `result`, `error` and `signed_out` are the common set (Codex ends a failed turn with a `result` that has `ok` false and yields no `error` of its own). Claude's adapter also yields the streaming kinds `message_start`, `text_delta`, `tool_start` and `tool_input`, and `limit`, `meta` and `retry` for the account's limits (`providers.py:302-382`); Codex's also yields `file_change` and `message_start` (`:624-637`); `agentd` takes each of them when present (`agentd.py:2984-3039`, and `file_change` at `:3079` and `:3175`). Give tools Claude's names (`Bash`, `TodoWrite`, `WebSearch`, `mcp__<server>__<tool>`), as `Codex.parse` does (`:652`), because `narrate.tool_step` reads those names to write the line above the pill.
4. Write `describe_command` (`:152` raises `NotImplementedError` in the base class and `src/bombadil/brain/describe.py:407` calls it). The sign-in hooks (`login_command`, `signin_command`, `signin_url_kind`, `code_from_url`, `signed_in`, `credentials`, `SIGNED_OUT`, `ends_when_signed_out`, `login_replaces`, `:146-186`) have defaults that do nothing special; override the ones your CLI's login needs.
5. Register it twice. Add it to `PROVIDERS` (`providers.py:753`) and to `config.PROVIDERS` (`src/bombadil/config.py:10`). `config.load()` raises `ValueError` for a name not in `config.PROVIDERS` (`config.py:57-58`); a name in `config.PROVIDERS` and not in `providers.PROVIDERS` raises `KeyError` when the pill offers the choice (`src/bombadil/agentd.py:2040-2042`); a name only in `providers.PROVIDERS` is never offered, which is how the `fake` provider stays out of the person's list (`providers.py:818`).
6. Add the words people say to `PROVIDER_WORDS` (`src/bombadil/launcher.py:76`), so "use acme" switches to it and typing its name answers the first-boot question (`agentd.py:672-675`), and its title to `REST_TITLES` (`:83`). `REST_TARGETS` is built from `PROVIDER_WORDS` and `launcher.match` reads `REST_TITLES[target]` (`:375`), so a provider with words and no title raises `KeyError` on "pause acme" (checked on 2026-11-08 on a copy of the tree). Add the page where its limit is raised to `rest.RAISE_PAGES` (`src/bombadil/rest.py:41`). If the CLI reports account limits, override `Provider.limit()` and `Provider.waiting()` (`providers.py:139,146`): both return `None` by default, so a limit is then an ordinary error and nothing rests. `Claude.limit` (`:425`) is the worked example. ### 2. Change the default model

Claude turns default to Sonnet and Codex has no default. `config.DEFAULT_MODELS` is `{"claude": "claude-sonnet-5-5"}` (`config.py:14`), and `Config.model_for(provider)` (`:28-32`) returns the `[models]` entry for the provider, else a bare `model` when the provider is the configured one, else the default, else nothing, which leaves the choice to the CLI. `agentd.main` passes `cfg.model_for(name)` to the provider (`agentd.py:3416`), and `Claude.command` adds `--model` when one is set (`providers.py:273-274`), as `Codex.command` does (`:585-586`).

1. Set it for every person with a `[models]` table in `iso/airootfs/etc/bombadil/config.toml`, or for one person in `~/.config/bombadil/config.toml`: `claude = "<name>"` and `codex = "<name>"` under `[models]`. `config.load()` reads the system file and then the user file and lets the user's top-level keys replace the system's (`config.py:43-59`), so a `[models]` table in the user file replaces the system one as a whole: on 2026-11-08, a user table that named only `claude` left Codex on its own default although the system table named a Codex model. To change the defaults themselves, edit `DEFAULT_MODELS` and `CLAUDE_MODELS` (`config.py:14-16`), the two names "use opus" and "use sonnet" switch between.
2. A bare `model = "<name>"` still works, for the configured provider only, so it follows whichever provider is configured: on 2026-11-08, `config.load()` after `save_user("codex")` handed the system `model` to Codex. Use `[models]` unless every provider you ship accepts the name. The running daemon and a restart agree: `AgentD.choose` writes back only a model the config file itself names and starts the other provider on `_model_for(name)` (`agentd.py:2244-2263`, `:3232`).
3. "use opus" and "use sonnet" (`launcher.MODEL_WORDS`, `launcher.py:60-64`) switch the model of the next turns of a session, for Claude only. `AgentD._switch_model` (`agentd.py:535-545`) keeps the choice in agentd's state file, `agentd-state.json` in the runtime folder (`:503-529`), and never in `config.toml`.

## Keeping your docs honest

The docs of a fork go stale the way its code does. [Documenting your piece](contributing/documenting.md) says where each kind of change is written down, what shape a page has, what the status words mean (`Shipped`, `Partly shipped`, `In progress`, `Designed`, `Idea`) and how `docs/tools/check_docs.py` checks links, anchors, diagrams and leaks. Two habits keep a fork's pages true. Change the page in the same commit as the code. Write a `Verified` line only after reading the code that backs the page. When you rename the product in code, rename it in the prose too: the checker finds a broken link and a leaked address, not an old name.
