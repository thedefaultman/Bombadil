# Known issues

> **Code:** `src/bombadil/agentd.py`, `src/bombadil/providers.py`, `src/bombadil/snapshots.py`, `src/bombadil/hypr.py`, `src/bombadil/paths.py`, `src/bombadil/appkit/placement.py`, `iso/airootfs/usr/local/bin/bombadil-install`, `iso/airootfs/usr/local/bin/bombadil-rollback`, `scripts/build-iso.sh`, `shell/shell.qml`
> **Verified:** 2026-10-01 against `main` at `26843d3`

This file lists the defects and gaps that are still true on `main`, so a contributor knows what is rough before building on it. Each item from the review of the first milestone was checked against the code on 2026-10-01, and only what is still true is listed. Line numbers refer to the commit above and move as the code changes; search for the named function, command or file if a line has shifted.

## Open

Within an area, the most severe item comes first.

| Area | What is wrong | What you see | Where in the code |
|---|---|---|---|
| Restore points and installer | The kernel and initramfs live on the EFI partition mounted at `/boot`. That partition is FAT and outside the btrfs root, so no restore point holds them, and an undo swaps only `@`. | After a turn that updates the kernel followed by an undo, the machine can boot the newer kernel against the older root's modules. | `iso/airootfs/usr/local/bin/bombadil-install:35-36,45-46,68`; `iso/airootfs/usr/local/bin/bombadil-rollback:13-15` |
| Restore points and installer | Restore points are never pruned. Each turn's snapshot is created without a cleanup algorithm, the installer enables only `greetd` and `NetworkManager` (no snapper cleanup timer), and each undo keeps the old root as `@.undone-<time>`. | On a long-lived install, free space on the btrfs volume shrinks steadily with use. | `src/bombadil/snapshots.py:43`; `iso/airootfs/usr/local/bin/bombadil-install:56`; `iso/airootfs/usr/local/bin/bombadil-rollback:13-14` |
| Restore points and installer | No test covers a failing `snapper`. When `snapper create` fails, `agentd` emits an `error` event (`no undo point for this turn: snapper failed (...)`) and the turn runs on without a restore point. `tests/test_agentd.py` has no `CalledProcessError` case, and no test runs `Snapshots._snapper` through a runner. | A change to that branch, or to the `snapper` command line, can pass every test. The cost is small: the person is told there is no undo point for the turn. | `src/bombadil/agentd.py:1251-1258`; `src/bombadil/snapshots.py:32-40` |
| `agentd` and bar supervision | Nothing restarts `agentd` or the Quickshell bar if it exits. The Hyprland start hook runs each once, with no supervisor or unit. The bar retries its socket connection to `agentd` but never starts it. | If `agentd` exits, the pill shows the connection as lost and prompts go nowhere until `agentd` is started again by hand (`hyprctl dispatch 'hl.dsp.exec_cmd("agentd")'`, which `bombadil-setup` also runs when nothing answers) or until the next login; `bombadil ask` prints `agentd is not running`. If the bar exits, it stays gone until `Super+Ctrl+Esc`, which restarts the bar and not `agentd`. | `iso/airootfs/etc/skel/.config/hypr/hyprland.lua:7-11,59`; `shell/shell.qml:80-105`; `iso/airootfs/usr/local/bin/bombadil-setup:30` |
| `agentd` state | The provider's conversation id (`self.session_id`) is held only in memory. Each turn writes it to `turns.jsonl`, but nothing reads it back at startup. | After a reboot or an `agentd` crash, the next prompt reaches an agent with no memory of the earlier conversation, although the provider CLI's own saved conversation is still on disk. | `src/bombadil/agentd.py:166,1488` (cleared on a provider switch at `:1074`) |
| `agentd` state | The turn counter (`self.turns`) and the turn ids (`self.next_id`) are in-memory counters that start at 0 whenever `agentd` starts. | After a restart, the `turns` count in the status message and restore-point descriptions (`turn:1: ...`) repeat numbers already used. Undo is not affected: it picks by snapper's own snapshot numbers. | `src/bombadil/agentd.py:167,171,1254` |
| Providers | A JSON object whose fields have an unexpected type (for example `"message": "odd"` where an object is expected) raises inside the provider's parser. Lines that are not JSON, and JSON that is not an object, are skipped. | The turn ends early. Text already streamed stays on screen, but the final result and the conversation id are lost, and the closing line is a Python exception message such as `AttributeError`. The Codex parser has the same weakness for an `item` that is a string. | `src/bombadil/providers.py:264,287,294,301-302` (Claude), `:430` (Codex); `src/bombadil/agentd.py:1324-1344,1194` |
| Providers | No test or check runs a real signed-in Codex conversation. The Codex adapter is covered by hand-written events and one signed-out recording. The VM smoke test checks `codex --version`, that the Codex sign-in page opens in the browser panel, that cancelling the sign-in ends it, and that port 1455 is freed. The desktop test runs the real Claude Code CLI against a scripted API (`tests/desktop/bin/claude` is only a wrapper) and has nothing for Codex. | A change to the Codex command line or event parsing can pass every test and still fail on a real turn, for example when resuming a session with the OS tools attached. | `tests/test_providers.py`; `tests/fixtures/codex-signed-out.jsonl`; `iso/airootfs/usr/local/bin/bombadil-smoke:81,253-256`; `tests/desktop/bin/` |
| Providers | Codex starts the OS tool server with its own small default environment plus the variables in `MCP_ENV`. The list forwards `XDG_RUNTIME_DIR`, `XDG_CONFIG_HOME`, `XDG_STATE_HOME`, `XDG_DATA_HOME` and `XDG_SESSION_TYPE`, the Hyprland, Wayland, X and D-Bus names, and the `BOMBADIL_SOCKET`, `BOMBADIL_APPS`, `BOMBADIL_STATE`, `BOMBADIL_SHARE`, `BOMBADIL_TURN` and `BOMBADIL_TURN_SNAPSHOT` overrides, but not `BOMBADIL_RUNTIME`, `BOMBADIL_CONFIG` or `BOMBADIL_DATA`, which `paths.py` reads for the runtime, config and data directories (the browser profile directory comes from the data directory). Nothing shipped sets them; only the test fixtures set the first two. | A contributor who sets one of them for development gets a tool server under Codex that looks in the default place, while `agentd` itself uses the override. | `src/bombadil/providers.py:370-373,410`; `src/bombadil/paths.py:16-37`; `src/bombadil/browser.py:33-34` |
| ISO and setup | The Claude Code and Codex command-line tools are installed with `npm install -g`, unpinned, and not by pacman: into `/usr` of the image at build time, and by `bombadil-setup` with `sudo npm install -g` if one is missing. | The CLI versions an image ships depend on the day it was built. `pacman -Syu` does not update them, and no package owns the files. | `scripts/build-iso.sh:19-23`; `iso/airootfs/usr/local/bin/bombadil-setup:12-13` |
| App placement | Unconfirmed. Whether generated apps open at separate cascade spots depends on two window rules that share one name. `place_app` in `hypr.py` adds `bombadil-app-<name>` with only a `move`; the app runtime then adds a rule of the same name carrying float, center, size and workspace. How Hyprland treats a repeated rule name has not been checked, and no test on a real Hyprland checks window positions. | If the later rule replaces the earlier one, each app opens centered, so apps open at the same spot. Each app lives in its own special workspace and only one is shown at a time, so the effect is small. | `src/bombadil/hypr.py:180-182`; `src/bombadil/appkit/placement.py:53-57`; `src/bombadil/appkit/runtime.py:504`; `iso/airootfs/usr/local/bin/bombadil-smoke:48` |
| `os-mcp` panels | The `files` panel has no class marker. Its command is `["nautilus"]` with no `--class=` or `--app-id=` argument, so `_launching()` cannot tell that its program is already starting, and only the 20 s wait for a window in `panel()` guards a second `show_panel` call. No test calls `Hyprland.panel`: `tests/test_hypr.py` has none, and `tests/test_mcp_server.py` replaces it with a fake. | A second `show_panel` for `files` while Nautilus is still starting and the wait has run out can start Nautilus again. Nautilus is single-instance, so the effect is small. | `src/bombadil/hypr.py:21-25,112-117,193-218`; `tests/test_mcp_server.py:11-23` |
