# History

This file records what was built and decided, in order, with dates and times in UTC.
An entry that starts with "Evening" instead of a time has no recorded minute, and its place in the list is approximate.
The current state is in [the roadmap](roadmap.md) and the plan is in the design briefs under [design/](design/).

## Timeline

### 2026-09-27

- 04:53 Foundation choices are written out with their alternatives, and all seven are confirmed at 04:55: Arch with btrfs and snapper (a snapshot is the undo); Hyprland first, with a custom compositor later; a VM first, with an ISO that also boots hardware; the official Claude Code and Codex command line tools as the engine, run by Bombadil's own session daemon; native QML apps through PySide6; one MCP server as the shared tool layer for both providers; Chromium driven over the DevTools protocol. See [foundation-choices.md](design/foundation-choices.md) and [ARCHITECTURE.md](ARCHITECTURE.md).
- 04:58 The repository is created.
- 05:08 The first milestone is committed on a branch and opened as draft PR #1 at 05:11.
- 05:15 Decision: the first real ISO boot is tested by building the ISO in a container and booting it headless in QEMU.
- 07:27 A review of the first milestone against the real behaviour of the tools it drives is written up: 34 findings, 13 of them blocking (for example, "undo that" rolled back to the snapshot of the undo turn itself). The confirmed fixes are folded into PR #1 by 07:35.
- 08:09 The ISO boots and the milestone works in a headless VM: the bar, the browser panel, a generated native app, and install plus undo across a reboot.
- 08:12 First design pass, [How Bombadil should feel](design/ux-brief.md), which serves the project's stated aim of an experience that is "stupidly simple to use, yet complete, capable and unique". All 29 decisions are confirmed at 08:27. At rest the screen is wallpaper and one pill, and a person learns three things: Super to talk, Esc to stop, "undo" to go back. The answer is the thing itself, something true is on screen within 200 ms, nothing asks for permission and nothing is hidden, "this" means what is in front of the person, what the agent makes is a real native app, recovery never goes through the part that broke, and there is one machine, one conversation and one memory that can be read. The status line and the pill as a launcher are built first.
- 08:31 A permissions file for Claude Code, `.claude/settings.json`, is added on `main`. It pre-approves the commands that automated coding runs use in this repository.
- 08:39 Decision: pull requests are merged as they are needed, once their checks pass, without a separate sign-off. They merge with a merge commit and are never force-pushed. Draft PR #2, the app kit, is opened.
- 09:01 PR #1 is merged: Bombadil first milestone. It holds:
  - `agentd`, the session daemon: one Unix socket, one turn at a time, a btrfs snapshot before every turn, and Claude Code or Codex run in full-access mode;
  - `bombadil-os-mcp`, the OS as tools: `show_panel`, `hide_panel`, `create_app`, `open_app`, `list_apps`, `app_template`, `screenshot`, `snapshot`, `list_snapshots`, `rollback` and `notify`;
  - `bombadil-app`, which runs a generated QML app from `~/Apps/<name>/` with hot reload, and the `Theme` and `AppWindow` QML components;
  - the Quickshell bar in `shell/shell.qml` and the `bombadil` terminal client;
  - an archiso profile for an Arch and Hyprland ISO with greetd autologin, a first-run provider setup and a btrfs and snapper installer, with `bombadil-rollback` as the undo;
  - `scripts/build-in-container.sh` and `scripts/test-vm.sh`, which build the ISO and check it headless in QEMU: a live session, install to disk, and undo across a reboot.
- 10:34 Second design pass, [Building on Bombadil](design/dev-brief.md). All 19 decisions are confirmed at 10:46. The coding tools run exactly as shipped and Bombadil hosts them. Coding sessions run in parallel but fenced (as the user, without sudo, in their own copy, with their own ports and undo), outlive their window and come back by name. "stop <name>" and "end <name>" are the one exception to the plain undo and Esc rules.
- 10:46 PR #3 is merged: live status line above the pill, and the pill as a launcher. For a person, a plain-words line says what the agent is doing while it does it, Stop ends the whole turn, queued prompts wait as chips, and a small exact list of typed words (an app or panel name, undo, stop, history) is handled by `agentd` without waiting for the model. For a contributor, `tests/desktop/run.sh` runs the real bar and agent in headless sway against a scripted API, and the VM smoke test sends key presses over QMP.
- 11:08 Third design pass, [Bombadil's Brain](design/brain-brief.md). All 17 decisions are confirmed at 11:12. The brain is a self-writing index shown as Focus (the default), Map (an overview) and Time (a strip under both). A graph view is not the main view. The build order is the index, Focus, search from the pill, brain tools for the agent, then Map and Time.
- 11:20 The passenger framing is adopted: the OS is built for the AI to drive, and the person is a passenger who gets what happens explained visually. It is worked out on 2026-09-29.
- 11:37 The first sign-in to Claude inside Bombadil, in a VM, works. The first conversation produces a native memory-monitor app.
- 12:18 PR #6 is merged: the details drawer closes. The drawer takes the keyboard, and Esc or pressing Details again puts it away. The VM smoke test checks it on real Hyprland.
- 12:21 Fourth design pass, [The Bombadil Desk](design/widgets-brief.md), delivered with mock-ups. It is confirmed on 2026-09-28.

### 2026-09-28

- 05:16 The desk design is confirmed with its 15 decisions, and the build of its first pieces starts. Widgets are modular, yield to whatever the AI brings and reserve no space. A widget is present only when it has something to say. Each has three faces: a card in a rail, a chip beside the pill and a mark on the pill's dot. The agent rearranges the desk only when asked.

### 2026-09-29

- 00:16 Fifth design pass, [Riding with Bombadil](design/passenger-brief.md). All 20 decisions are confirmed at 00:28. It has six pieces: a "why" line and an "after reading" line for each step, pictures of the machine drawn from the machine, a browser with an orange frame and a takeover, promises that survive a restart, readable memory, and watchable updates. Installing updates nightly is cut, and downloading them stays. The first two pieces are built first.

### 2026-09-30

- 17:00 PR #7 is merged: VM fixes, batch 1. A Super tap gives the pill the keyboard and the pill hands it back when idle, the launcher check in the smoke test is exact, and a QEMU guest runs at 1920x1080 instead of the 640x480 it reports.
- 17:09 Sixth design pass, [Bombadil's voice](design/voice-brief.md), is written. The plan is accepted at 17:24 with its recommended picks. Right after sign-in one small card asks what to call the person and offers three voices: Merry, Plain and Quiet. The welcome is one line above the pill that fades. The voice changes words and never facts, and it reaches greetings, goodbyes and the last sentence of a reply, not the working line.
- 17:15 The design pass [Bombadil tends itself](design/self-improvement-brief.md) is written. It is accepted at 17:32 as options 1a, 2a and 3a. A repeated request may become anything that fits (a word, a widget, an app, a routine, a reminder or a remembered preference), with one recommended and a tap to choose. A "noticed" chip shows only when something needs an answer, and a line in the welcome-back card says what changed, each with Undo. Before and after pictures come before any change the person would notice. Bombadil may fix its own bugs only while the person is away, confirmed once and each fix with Undo. Counting requests and the first offers are built first, then the self-checks.
- 17:39 [Should Bombadil use Rust?](design/rust-question.md) is answered with measurements, and a plan is chosen within the hour: not yet. Python and QML stay, because Bombadil mostly waits on the model and generated apps must stay QML. Rust fits later in the custom compositor and, only if a measurement says so, in the brain's file watcher. The plan is to fix three design problems the survey found (no restart after a crash, one unexpected line from the CLI ends a turn, a repeated block in the watcher's messages) in Python first.
- 18:03 PR #11 is merged: a project chronicle (later replaced by this file), a docs index, the design briefs, the published pages of the briefs as standalone HTML, the first-milestone review notes and screenshots from headless VM runs are added under `docs/`.
- 18:39 PR #9 is merged: the desk. The shell gains two rails and strips beside the pill. The `Now` card shows the route of a turn, the `Watching` card shows background jobs, watchers and timers, and the `Needs you` card shows what waits on the person. `agentd` gains a jobs registry (jobs, watchers and timers as systemd user units whose records survive a restart), a `job` tool and a `desk` tool in `bombadil-os-mcp`, and the turn's plan. The desk's state is kept in `desk.toml`.
- 19:18 PR #5 is merged: sign in to Claude or Codex from the pill. First boot asks which AI should run the machine, and the provider's own login page opens in the browser panel's Chromium, which has a profile of its own and a managed policy. `bombadil-browser` is the default browser, the sign-in carries over to an install, and the smoke test runs the whole round trip against a stand-in login. PR #13 follows at 19:22 with a one-line fix to a desk test for the setup greeting this pull request added.
- 19:41 PR #8 is merged: VM fixes, batches 2, 4 and 5. The ISO ships audio support and an active package mirror, the installed system boots straight in with the GRUB menu hidden unless Esc is held, each app opens on its own spot, and Alt+Space also opens the pill for hosts, such as a Windows-hosted VM window, that keep the Windows key. Claude loads only Bombadil's own tools, a long think is not reported as a dead connection, a limit message keeps its reset time, Stop leaves an empty result, and the status line no longer sticks on "Saving a restore point" when the provider is unreachable.
- Evening: The three questions of the seventh design pass, [Bombadil, installed](design/installed-os-brief.md), are answered, and the pass is written the same day. Four things are decided once, at install and before anyone else installs: the disk layout, encryption with one password, where GRUB lives, and which files the package manager owns. Bombadil's own files reach installed machines as packages from its own signed repository. The install card comes before any public download, and the stick also repairs and reinstalls while keeping files. New installs lock the disk with one password and a recovery key, and whole disks install first, next to another operating system after.
- Evening: Round one of the identity pass, which offered three marks (A the b, B the dot on the i, C the pebble), is answered: the pebble's motion and B's drawn letters are favoured, and the pebble needs more identity of its own.
- 22:25 PR #15 is merged: run Bombadil in a VM window on Windows through WSL (`scripts/bombadil-vm.cmd`, `scripts/wsl-vm.sh`). `refresh` moves an installed VM to the checked-out commit and keeps its disk, `reinstall` asks before it wipes, and `scripts/vm-tools/` holds the helpers that drive a running VM: keys, clicks and screenshots over QMP, a serial shell, and smoke checks.
- Evening: Round two of the identity pass (`identity-brief.md`) chooses the mark: E, the riding b. It is a smooth three-sided stone (a rounded Reuleaux triangle, the same width in every direction) with a lowercase b cut through it. While the machine works the stone turns and the b stays level. The mark is ink and colour is the state. The orange `#d97757` stays, only on the working stone and on the dot of the i in the name `bombadil`, and the mark is never orange or on an orange tile. Each pill state reads without colour: rest is still, listening leans, working rolls, needs you knocks, done hops once, stopped is a square, offline is a broken outline. There is no boot splash and no logo wallpaper, and nothing is borrowed (no imagery from other works, no face, no mascot). The design system is written down with it: colour, type, shape, space, motion, depth and icons, with the token names in `share/qml/Bombadil/Theme.qml`.
- Evening: The three questions of the design pass [Bombadil at work](design/everyday-work-brief.md) are answered, and the pass is written the same day. Bombadil shows and answers in its own views for anything the person glances at or answers in a sentence (one Mail view for every account, message cards, today), and work inside a tool stays in the browser panel. Only the person's own press sends mail or a message. Mail is built on Thunderbird running unseen. Writing for a student is not refused, and every help is logged.
- 23:14 PR #2 is merged: the app kit and the `bombadil-apps` skill, opened as a draft on 2026-09-27. A skill for Claude Code and Codex teaches the agent to build apps, with an OS-styled component kit (controls, lists, tables, forms, charts), native bindings that need no Python (system and process readers, a store, an encrypted vault, a command runner, text files, the clipboard, the agent), and a runtime that hot reloads an app in its window and keeps the old interface when a reload fails. `bombadil-os-mcp` gains `app_guide`, `check_app` (loads an app offscreen and reports errors with a screenshot), `show_app`, `hide_app`, `close_app` and `app_status`, and `create_app` checks what it writes. The bar shows a chip per running app, and a password manager and a memory viewer are shipped as examples built from the skill alone.
- 23:28 PR #17 is merged: one set of colours, sizes and type for the shell and the app kit. The pill, the line and the chips read the kit's `Theme` instead of 22 hard-coded colours, the shell sets Inter everywhere, and `bin/bombadil-shell` starts Quickshell with the kit on its import path. Error and irreversible reds become the kit's `bad`, and the system amber becomes `warn`. A test fails when the desk's plain values drift from the tokens.
- 23:35 PR #18 is merged: the mark in the machine. `shell/Stone.qml` replaces the pill's dot with the stone and its states, which gain starting, listening, needs you and stopped. The image installs the icon, `docs/brand/` holds the mark, tile, lockups, avatar and social preview, the README opens with the lockup in a dark and a light copy, and `share/grub/bombadil` is the theme for the installed disk's password screen. Reduced motion pulses instead of rolling.
- 23:53 PR #10 is merged: why lines and pictures from the machine, the first two pieces of the passenger design. The agent's sentence before each step is kept as its reason, shown on hover and under a marked step's command. A step that follows a read of something from outside says "after reading" it. `show_card` and `system_map` draw a picture above the pill with the kit's `Diagram` component, and `system_map` reads the real machine instead of the model's memory. A click on a box opens what it names, and receipts show before and after.

### 2026-10-01

- 00:26 PR #20 is merged: the design pass on running out of tokens, "The poor man switch", is added under `docs/design/` as a brief and a page. It proposes making running out a state that is said once with the time it ends: asks are held rather than failed, a switch pauses a provider by hand, and the pill still answers a sentence with what it finds on the computer. Apps, background jobs, the browser, files, launcher words and undo keep working without the model.
