The shell is the whole visible interface at login: one Quickshell program that draws a pill at the bottom of every screen, with the line and the chips above it (the line also says what other services ask agentd to say, such as new mail, and agentd's welcome when the person arrives; a card above the line asks once what to call the person, [the welcome line and the name card](#the-welcome-line-and-the-name-card)), a row of chips above its left end while coding sessions exist (a chip per project with a dot per session, [the session dots](#the-session-dots)), the stone at its left end (a click on it opens the AI card), a card above the pill where each desk widget is set to Keep, When needed or Off (the word `widgets` opens it, [the Widgets card](#the-widgets-card)), the picture host (which also holds the cards of the person's messages, tasks and connections: [the cards of the connections](#the-cards-of-the-connections)), the windows of the desk and the wallpaper under everything. The bar also owns the desktop's notification name and passes each notification to agentd ([the notification server](#the-notification-server)). It keeps no conversation: it turns what agentd says into what is on screen and sends back what the person types or clicks. It exists so that something true is on screen the moment Enter is pressed, and so that stop, undo and the launcher words never wait for a model. The states for an AI that is out of plan or paused are described here from the shell's side and in [the poor man switch](poor-man-switch.md) from agentd's; notices are described here and in [mail](mail.md); the welcome line and the name card are described here from the shell's side and in [Bombadil's voice](voice.md) from agentd's; the cards, their box and button, and the notification server are described here from the shell's side and in [connect.md](connect.md) and [the contract](../CONNECT.md) from the service's and agentd's; the Widgets card is described here from the shell's side and in [the desk](desk.md#your-desk-keep-when-needed-off) from the desk's and agentd's.

## How it works

```mermaid
flowchart LR
    agentd["agentd socket"] -->|"one JSON object per line, root.handle"| pill["PillState"]
    agentd --> desk["DeskState"]
    agentd --> dev["DevState"]
    agentd -->|"notification_invoke, notification_close"| notif["Notifications"]
    notif -->|"notification"| agentd
    pill -->|"mode, line, notice, risk, command, flash"| line["StatusLine, NoticeChips"]
    pill -->|"face"| stone["Stone"]
    pill -->|"queue, setupActions, foundChips, card, aiOpen, aiRows, personaAsk"| chips["QueueChips, SetupChips, FoundChips, CardHost, AiCard, PersonaCard"]
    pill -->|"summoned(text)"| focus["root.summon, keyboard focus"]
    desk -->|"needsYou"| pill
    desk -->|"windowOpened"| pill
    desk -->|"capsule, pillWidth, strips, widgetsOpen, widgetList"| bar["the pill's width, the desk windows and the Widgets card"]
    dev -->|"sessions, line"| dots["SessionChips, SessionPeek, the pill's empty line"]
    hypr["Hyprland events"] --> cover["HyprCover"]
    cover -->|"setWindows"| desk
    hypr --> appchips["app chips"]
```

**Start.** On `hyprland.start` Hyprland imports the session's environment into the user manager and restarts two user units: `systemctl --user import-environment && systemctl --user restart bombadil-agentd bombadil-shell`. It starts no notification daemon: the bar's own server owns the name ([the notification server](#the-notification-server)). It starts one `foot --server`, so that a coding session's window rises at once ([coding-sessions.md](coding-sessions.md)). Then it hands Mail's user unit this session's screen and restarts it (`systemctl --user import-environment WAYLAND_DISPLAY HYPRLAND_INSTANCE_SIGNATURE XDG_CURRENT_DESKTOP && systemctl --user restart bombadil-mail.service`, `hyprland.lua:7-24`; [mail.md](mail.md)) and does the same for the browser service's (`bombadil-browserd.service`; [connect.md](connect.md)). The two units start again about a second after they die (`Restart=always`, `RestartSec=1`; [session-services.md](session-services.md)). `bombadil-shell.service` is `After=bombadil-agentd.service` and its `ExecStart` is `/usr/local/bin/bombadil-shell`, the wrapper `bin/bombadil-shell`: it puts `share/qml` on `QML2_IMPORT_PATH` and runs `quickshell -p <root>/shell/shell.qml`. `shell.qml` makes one `PillState`, one `DeskState`, one `DevState` and one notification server (`Notifications.qml`, in a `Loader` of its own) for the whole session and one `PanelWindow` per screen (`Variants { model: Quickshell.screens }`). The line, the chips, the session dots and the stone read the same state on every screen. What differs per screen is the keyboard, the pill's width, the desk's strips and, for the welcome line and the name card, whether they show (only on the screen that had the focus when they came). `shell.qml` also makes two `IdleMonitor` blocks ([the welcome line and the name card](#the-welcome-line-and-the-name-card)) and a `Wallpaper` ([the wallpaper](#the-wallpaper)).

**Connecting.** The socket path is `$BOMBADIL_SOCKET`, else `$XDG_RUNTIME_DIR/bombadil/agentd.sock`. A comment in `shell.qml` says a Quickshell `Socket` that failed to connect does not retry, so each attempt is a fresh `Socket` made from the `link` component. While `root.connected` is false a 1500 ms `Timer` (running from the start) destroys the last socket and makes the next. When the connection state changes, the shell sets `root.connected` and `deskState.connected`; a connect sets `pillState.connected`, and a drop calls `pillState.lost()`, `deskState.lost()` and `devState.lost()`. agentd greets each client that connects with `status`, `entries`, `setup`, a `notice` for each notice nobody has ended, the card of a connection that is still open (a `card` message), each draft that a press left half done (a `proposal` message), the `dev` snapshot (the coding sessions), the Tips card (a `tips` message when Tips is on, which the shell does not read) and, while there is one, the `away` card (`AgentD._greet`, `src/bombadil/agentd.py:640-661`, [agentd.md](agentd.md#the-socket)), and `DeskState` asks for `desk get` as soon as it is connected, so a restarted bar is told what is running without any state of its own.

**Handling.** `SplitParser` hands each line to `root.handle`, which parses it (a line that is not JSON is dropped) and gives the object to `pillState.handle`, `deskState.handle`, `devState.handle` (which reads only `dev` messages) and the notification server's `handle` (which reads only `notification_invoke` and `notification_close`). The three state objects emit `outgoing(msg)`, and so does the notification server (a `Connections` in `shell.qml` passes it on); `root.write` sends it as one JSON line and does nothing while the socket is down. The pill's methods that send (`stop`, `unqueue`, `undo`, `details`, `setupAction`, `openThing`, `noticeAction`, `dismissNotice`, `openFound`, `setAi`, the opening half of `toggleAi` and, for a card, `openReply`, `press` and `cardAction`) check `_offline()` first and flash "Not connected to the agent yet." on the line; `submit` says the same as a `local` line and keeps the typed text; `closeDetails` stays silent, and so do `proposalEdit`, `proposalShown` and the messages `dismissCard` sends, which go only while connected ([the cards of the connections](#the-cards-of-the-connections)). So a click while disconnected is answered, not lost. The methods of the voice (`presence`, `personaAnswer` and `personaSkip`) do not check: the name card cannot be up while disconnected (`lost()` takes it away), and a `presence` sent while the socket is down is dropped by `root.write`.

**Hyprland.** Three things come from the compositor and not from agentd. The app chips are built from `Hyprland.toplevels` whose workspace is named `special:app-<name>`, refreshed on the raw events `openwindow`, `closewindow` and `movewindowv2`, with the shown workspace tracked from `activespecial`. What puts an app's window in that workspace is `src/bombadil/appkit/placement.py` (see [app-kit.md](app-kit.md)): before the window first maps, `prepare()` adds a runtime window rule named `bombadil-app-<name>` that floats and centres it at its own size, shrunk to the screen, with `workspace = special:app-<name>`. The static `bombadil-apps` rule in `hyprland.lua` floats and centres every `bombadil-app-*` window at 540 by 660 and names no workspace. `HyprCover` reports where the windows are to `DeskState.setWindows`, which decides whether the desk's cards fold and whether the pill becomes a capsule, and emits `windowOpened` when the list grew (`shell.qml:116` connects it to `pillState.windowOpened()`, which puts a picture away: [the picture host](#the-picture-host)). The app chips send nothing to the desk. The third is `PillState.fullscreen`, which `shell.qml` binds to whether the focused monitor's active workspace has a full-screen window (`hasFullscreen`, `shell.qml:53`); a welcome line is dropped while it is true ([the welcome line and the name card](#the-welcome-line-and-the-name-card)).

### Keyboard focus

On Hyprland the pill takes keys only while it is summoned. `root.summonedOn` holds the name of the one screen whose pill has the keyboard (`""` for none), so only one pill holds it at a time.

```mermaid
stateDiagram-v2
    [*] --> Released
    Released --> Summoned : Super tap, Alt+Space, a click on the pill, a summon with words, the name card asking, a card's box asking or the word widgets
    Summoned --> Released : second tap, Enter, Esc on an empty pill, in a card's box or with the Widgets card up, click away, idle, hand-off
```

| Compositor | Not summoned | Summoned |
|---|---|---|
| Hyprland (`HYPRLAND_INSTANCE_SIGNATURE` is set) | `WlrKeyboardFocus.None` | `WlrKeyboardFocus.OnDemand`, plus a `HyprlandFocusGrab` on the window |
| Any other (the headless sway test) | `OnDemand` | `Exclusive` |

The comment at `shell.qml:349-356` gives the reasons: the grab gives the pill the keyboard at once and a click anywhere else takes it away; going from `OnDemand` back to `None` makes Hyprland hand the keyboard to the window the person was in; and `Exclusive` is never used on Hyprland because Hyprland ends any grab when a layer turns exclusive, so the keys went to the window under the pointer. No pytest test runs the focus, mask or layer rules, and the desktop test and the smoke exercise them only in part (see [Tests](#tests)).

### The pill's modes

`PillState.mode` is what the line shows. `optimistic` is a flag inside `working`: "On it" was drawn on Enter, before agentd confirmed a turn.

```mermaid
stateDiagram-v2
    [*] --> idle
    idle --> onIt : Enter
    onIt --> working : turn_start
    working --> closing : turn_end
    closing --> idle : fade or Esc
    onIt --> local : answered without a turn
    working --> local : connection lost
    local --> idle : fade or Esc
    idle --> setup : AI not ready
    setup --> idle : AI ready
    idle --> resting : AI rests
    resting --> idle : fade, Esc or AI back
    idle --> welcome : welcome message
    welcome --> idle : touch then fade, typing, Enter or Esc
```

The diagram is the main path. The rest, from `PillState.qml`: Enter from `closing`, `local` or `welcome` goes to `onIt` as it does from `idle`. `turn_start` goes to `working` from any mode, and a `status` event inside a turn rewrites the line without leaving `working`. An answer agentd gives without the model (a `local` event, or an error with no turn) makes mode `local` from `idle`, `closing` or `setup`. A turn that is queued and ends before it starts goes from `onIt` to `closing`. When a line fades or `Esc` puts it away while the AI is not ready, the setup line comes back instead of `idle`. A setup that becomes ready with a line to say ("Signed in to Claude. Ask me for anything.") goes to `local` for 8 s; one that follows `resting` says "Claude is back. Running your 3 waiting asks." the same way, and `PillState` keeps that line as a flash over the turn it starts (`_backLine`). `resting` is also entered from `closing`, `local`, `setup` and `working` ([While the AI rests](#while-the-ai-rests)). `welcome` is entered only from `idle` ([the welcome line and the name card](#the-welcome-line-and-the-name-card)). A notice is not a mode: it shows over `idle`, or over any mode but `working` when it is a warning ([Notices](#notices)).

| Mode | When | What shows | Leaves when |
|---|---|---|---|
| `idle` | nothing to say | no line: `StatusLine` has height 0 and opacity 0, and its timer is stopped (a notice alone shows the line but does not start the timer) | any of the rows below |
| `working` | `submit` (as `onIt`, the line "On it"), or `turn_start`, or a `status` message that reports a running turn the bar did not know of (the line "Working") | the live line, one line long, its seconds counter from the first second, and an edge: amber for `risk` `system`, red for `irreversible`. A marked step also shows its exact `command`, its `because` and its `after`. A `local` answer shows over the line as a flash and the line comes back | `turn_end`, a `local` answer when no turn was confirmed, `lost()` |
| `closing` | `turn_end` | the first of these that applies: the stop line when the turn was stopped (agentd's `line`, else "Stopped."); for a turn the limit stopped halfway (`requeued`), agentd's `line` (what it changed, and when it carries on) as a plain step line, never an error; when the turn had an error and its result was not ok or there was none, the error's first two lines with a red edge; the result text (up to four lines); the summary; "Done." (a turn with an error and an ok result shows the result); "can't be undone" after an irreversible step; a click on the line is Details. Details and Undo (while `sticky`) are also buttons, but only when the turn `changed` something or was `irreversible` | the fade, `Esc`, the next prompt or turn |
| `local` | an answer agentd gave without the model, an error with no turn, "Lost touch with the agent. Reconnecting.", "Not connected to the agent yet.", or the one-time "ready" line | the text; a red edge for an error | the fade, `Esc`, the next prompt |
| `setup` | `setup` message whose state is not ready (`choose`, `signed_out`, `offline`, `signing_in`) | the setup line and the `SetupChips`; a red edge when its tone is `error` | the state becomes ready |
| `welcome` | a `welcome` message while the mode is `idle` and nothing else holds the line | agentd's words as a plain step line, on the one screen that shows it | the fade (8 s after the first touch, 15 s for a first hello, at most 30 s after it appeared), typing, Enter or Esc in the pill, a `persona_ask`, `lost()`, or anything that takes the line: a prompt, a turn, an answer or an error from agentd, the setup line |
| `resting` | a `setup` message with state `resting` (when it flips or its words change), a summon while resting, an ask typed while resting, or `_putLineAway` when the resting line was owed (a turn or a line with Undo held it); also the line of what was found | the setup line of the resting state, as a plain step line with no red edge, the `SetupChips` under it (Resume, Raise the limit, Try again) or the found line with the `FoundChips` | the fade (12 s), `Esc`, a turn, state `ready`, or a sign-in problem (mode `setup`) |

`ready` is `setupState` of `""`, `"ready"` or `"checking"`. While it is false, a typed line is still sent as a `prompt`, no "On it" is drawn, and agentd queues it (a line that starts with `!` is the exception and runs). `resting` (`setupState` `"resting"`) is not ready either and is handled before that case in `submit`: the prompt is sent and waits as a chip, and the resting line shows instead of "On it". A turn has the line while it runs: a `setup` message that arrives mid-turn is stored, and while the AI is still not ready the setup line comes back when the turn's line goes (`_putLineAway`); a ready "Signed in" line that arrives mid-turn is not shown later. The "Signed in" line is said once to a bar that saw the state change, and never to a bar that has just started.

### The stone

`Stone.qml` draws the mark in the pill's left slot: a 24 by 24 item with an 18 px rounded Reuleaux triangle and a lowercase b cut through it. `PillState.face` decides the face (first match wins, in this order), and `shell.qml` changes `rest` to `listening` on the screen that holds the keyboard (`shell.qml:720`). For its first `settle` (400 ms) the stone is painted the resting green whatever its face says, then follows it (`Stone.qml:34-41`): the comment says the scene graph dropped a colour change made in the first frames after the bar started, so a face that went `starting` and then `rest` stayed orange. A bar that connects within 400 ms never shows the orange.

| `face` | `PillState.face` gives it when | Stone |
|---|---|---|
| `starting` | not connected, agentd has not answered since the bar started, and the 15 s `booting` timer in `shell.qml` is running | orange, rolling, after the first 400 ms; the placeholder says "Starting" |
| `offline` | not connected, and agentd was seen or the boot window is over | broken red outline with the b as a red line |
| `needs` | `needsYou` (the desk sets it while a coding session waits), or mode `setup` with state `choose`, `signed_out` or `offline` | amber, two knocks and a breathing glow on a 1.6 s beat |
| `working` | `busy`, `optimistic`, mode `working`, or setup state `signing_in` | orange, a third of a turn per second about the b, which stays still |
| `resting` | `setupState` is `resting`, or mode `closing` and the turn was cut off by the limit (`requeued`); checked after `needs` and `working` and before `stopped` and `done`, so a waiting coding session still shows `needs` while the AI rests, and the stone does not hop | a whole 1.5 px outline in `muted` over a 30% `muted` fill, the b cut in `ground`, still (`Stone.qml:135-161`) |
| `stopped` | mode `closing` and the turn was stopped | a 12 px muted (grey) rounded square: the shape of the Stop button's square, not its orange |
| `done` | mode `closing`, not stopped, not an error | green, one 700 ms hop, then still |
| `rest` | otherwise, including a closing line that is an error | green, still |
| `listening` | `rest` on the screen whose pill holds the keyboard (`shell.qml:720`) | green, leaning 6 degrees toward the text |

The motion, from `Stone.qml`: the roll holds 300 ms, turns 120 degrees in 550 ms on the curve (0.55, 0, 0.3, 1) and holds 150 ms; the knocks tip 8 degrees (192, 160, 160 and 160 ms, then a 928 ms wait); the glow runs 0.25 to 0.6 to 0.25 in 560 and 1040 ms and reaches 16 px from the stone's centre, past the 24 px slot into the pill's padding; the lean eases over 240 ms on (0.16, 1, 0.3, 1) (`Stone.qml:60`). `stopped`, `offline` and `resting` are shapes of their own (`drawn` is false for them, `Stone.qml:31`), and nothing in them moves. The b is drawn in `ground` (default `Kit.Theme.glassPill`), so it reads as a cut only on a flat surface of that colour. With `reducedMotion` the roll becomes an opacity pulse (to `Kit.Theme.pulseLow` and back, 500 ms each way), the knock stops and the glow is held at 0.45, the hop becomes a 600 ms fade in from 0.3, and the lean is instant. `shell.qml` reads `BOMBADIL_REDUCE_MOTION=1` into `root.reducedMotion` and writes it to `Kit.Theme.reducedMotion` (a `Binding`, `shell.qml:37`), the one switch the whole interface reads ([Motion](../MOTION.md)); the stone and `Wallpaper` are handed `Kit.Theme.reducedMotion` (`Wallpaper` then shows its picture and its dimming without a fade). Nothing in the repository sets that variable. The look is explained in [the design system](../design-system/README.md#the-mark-and-its-states) and why in [the identity brief](../design/identity-brief.md#the-stone).

### The AI card

A tap on the stone while no turn runs calls `pillState.toggleAi()`: it opens `AiCard.qml` and sends `{"type": "ai", "op": "get"}`. agentd answers with an `ai` message of `rows: [{name, title, state, text, on, enabled, current}]` and sends it again on every change. ### The notification server

`shell/Notifications.qml` is the bar's own server for the desktop's notification name, `org.freedesktop.Notifications`, in place of a separate notification daemon: the image has none and the start hook starts none ([The Hyprland config the ISO ships](#the-hyprland-config-the-iso-ships)). It draws nothing. `shell.qml` makes one for the session in a `Loader` with `source: "Notifications.qml"`, so a Quickshell without the service costs the notifications and nothing else. A `Binding` gives it `link`, which is `root.connected`, and a `Connections` writes its `outgoing` to the socket (`shell.qml:72-83`). What the person sees of a notification, and what Reply and Open do with it, are agentd's ([connect.md](connect.md), [the contract](../CONNECT.md)): it posts a notice with `source` `notify`, which the shell draws as any notice ([Notices](#notices)), and a Reply on it opens a card ([the cards of the connections](#the-cards-of-the-connections)).

| What | What the server does |
|---|---|
| What it says it can do | actions and a body, and nothing else: no markup, no links, no images, no inline reply and no persistence across a restart of the bar (`keepOnReload` is false). Chromium sends clicks and actions only to a server that advertises `actions`, so that one matters (the file's comment) |
| A notification arrives | it is kept tracked, so that it can still be acted on (Quickshell destroys one that is not tracked as the signal returns), and sent to agentd as `{"type": "notification", "id", "app", "summary", "body", "urgency", "icon", "actions"}`. `urgency` is `low`, `normal` or `critical`; `actions` are at most 8 of `{id, label}`; every text is cut at 2000 characters and passed on as it came, since agentd makes it plain |
| The same id again | an app updating a notification: the one held under that id is let go and the new one is kept and sent |
| agentd is away | the notification waits and goes once when `link` turns true. One that agentd lost with a restart is not sent again, because it would be a notice for something the person may have seen |
| How many are held | at most 64: the 65th makes the oldest be dismissed |
| `notification_invoke {id, action?}` | invokes the named action, else the notification's `default` one (for a browser tab, bringing the tab forward), then lets the notification go. With no action to take it is dismissed instead. An `id` that is not a number, or not held, does nothing |
| `notification_close {id}` | dismisses it: the app is told it was put away |
| An app closes its own | it is let go; a later word from agentd about it finds nothing |

### The launcher mirror in `PillState`

`PillState.entries` is the `entries` message: the names the launcher opens (`kind` `app`, `project`, `session`, `panel`, `widget` or `command`, each with `words`; the projects and sessions are agentd's `dev` names, such as `claude acme`, so Tab completes them and the hint shows for them too). `completion(text)` returns the rest of a name for Tab, and `exact(text)` names what an exact word would open, drawn as `↵ <name>`. Both mirror `launcher.py`: only spaces, hyphens and underscores fold away (`_key`), a line that starts with `!` is never a word, a question mark at the end keeps a widget or `desk` for the agent, and a widget's name counts only after one of `open`, `show`, `close`, `hide` or, for a widget whose entry has `keep` set (the widgets on the Widgets card, `WIDGETS[w].listed` in `launcher.py`), `keep`. After `keep` the tail ` on the desk` or ` on my desk` is left out (`_keepTails`), so `keep machine on the desk` shows `↵ Machine` and `keep mach` completes with Tab, while `keep calendar` and `keep alive` are for the agent. The hint exists so the person sees that a word opens here without the model. It is a hint: agentd decides.

### The picture host

`CardHost.qml` draws `pill.card` (a diagram from `show_card`, `system_map` or a receipt) above the line with the kit's `Diagram`: a title, "from this machine" or "drawn by the agent" (or "drawing…" while partial), a close ×, the diagram in a scrolling `Flickable`, and one `say` sentence. A card of a connection has the same frame, with the card's `via` in the place of the note on where a picture came from and a face in the place of the diagram ([the cards of the connections](#the-cards-of-the-connections)). It keeps the last card while it fades out. Its height is not animated: the bar's window is as tall as its contents, so a height that grew over a few frames would resize the window every frame, and Hyprland's layer animation would swing the pill with each resize (the file's comment; `hyprland.lua` turns that animation off, [below](#the-hyprland-config-the-iso-ships)). The card takes its room at once, fades in and rises 14 px inside it, and gives the room back once it has faded out. `PillState` takes a card from an `event` `card` or from a `card` message (types `diagram`, `message`, `task` and `list`; `{id, gone}` takes one back). One card is shown at a time and a newer one replaces it. A box that names something calls `pill.openThing(target)`, which sends `open` (or `details` for a turn). What a card holds and how it is validated is in [cards-and-pictures.md](cards-and-pictures.md).

### The cards of the connections

Three kinds of card come from the person's connections ([connect.md](connect.md), the contract in [CONNECT.md](../CONNECT.md)): a `message` (the last messages of a thread and a box to reply in), a `task` (an item of a work tool, its fields and a button) and a `list` (rows with marks and buttons: the unread messages, "Connected here"). agentd checks each with `cards.py` before the bar gets it ([cards and pictures](cards-and-pictures.md)). `PillState` takes only the kinds in `cardKinds` (`diagram`, `message`, `task`, `list`) and, for the three kinds that come from connections, only a card with a string `id`, because a face keys its box on it. One card is shown at a time, whatever its kind. `CardHost` keeps the frame (the title, the card's `via`, the ×, the one `say` sentence) and holds the body in a `Loader` chosen by the card's `type`, which builds a face when the card comes and drops it when another kind does, so a box or a timer is never one card's left-over in the next. Every word on a face is another person's and is drawn as plain text, never as markup.

| Part | What it does |
|---|---|

A card with no reply has no box and only its way out. A card whose reply is of kind `copy` (made from a notification) has the same box and a button "Copy and open" that sends nothing: `copyOpen` sends `card_action` `copy_open` with the typed words, and agentd puts them on the clipboard and brings the page forward |

| `ListFace.qml` | a row each: a mark that is a shape as well as a colour (`ok` a tick in green, `warn` a triangle in amber, `bad` a cross in red, `new` a dot in orange, `gone` a dash with a dim title, `active` a ring in blue), a title, a line under it (two lines at most), when, and up to two buttons. A message or a task is at most 560 wide and a list at most 480 (`CardHost.preferredWidth`, which the `cardHost` item in `shell.qml` reads), and never wider than `max(360, win.pictureMax)`. A card of a connection is drawn on one screen and a picture on every one. A message or a task has a box, and two boxes for one draft would be two people typing into one (the comment in `shell.qml`). `root.cardScreen` is set when the card's id changes, to the screen that holds the keyboard, else the focused one, and cleared when the card goes; `shell.qml` binds each host's `onThisScreen` to it, and every screen draws the card when `cardScreen` names a screen that is not plugged in. A `diagram` is drawn on every screen whatever `cardScreen` says. Only the screen that draws the box tells the pill whether the person is in it (`Draft._compose`), since another screen's face holds a stale mirror of the card and never has the focus.

While the person is in a box (`PillState.composing`: the box has the keyboard, or has words in it) the card is not taken away by what takes a picture away: the next turn, a failed picture, a launcher open or a window opening ([the picture host](#the-picture-host)). A card nobody has typed in goes as a picture does.

What the box and the button do together is `Draft.qml`, which draws nothing, and the shell reports what the card has drawn so that agentd lights the button only for what is on the screen:

| What | What the shell does |
|---|---|
| The first key in a box with no draft | asks agentd for one, `{"type": "proposal", "op": "open", "kind", "target"}` (`PillState.openReply`). What was typed meanwhile is kept and sent once the card comes again with the draft's id |
| Typing | 150 ms after the last key, `{"type": "proposal", "op": "edit", "id", "content"}`: the words in the box, as text for a reply and as the object of field values for a task. Nothing is sent while the socket is down |
| What the card drew | 200 ms after the last key and on the frame that holds the words (the window's `frameSwapped`, and after 500 ms at the latest if no frame comes), `{"type": "proposal", "op": "shown", "id", "content"}`; an `edit` always goes before it. It is also said when the card is first drawn and whenever agentd hands the bar the whole card again (`cardEpoch`), as it does for the open card when a bar reconnects |
| agentd's word on the draft | a `proposal` message: the open card takes the draft's `state`, `ready`, `fingerprint`, `receipt`, `warnings` (plain, at most 240 characters each) and `note`. Its `content` goes into the boxes only for a draft the person has not typed in and whose boxes are empty or just opened: a person who is typing is never written over, and one who emptied the box does not get the old words back from a late answer. Characters agentd took out because they draw as nothing (a paste from a page often has some) come back as the cleaned words while the box still holds exactly what was pasted. A draft that is `discarded` takes the card away |
| The button | live only while agentd says the draft is `ready` and its `state` is `open`, the boxes hold exactly the draft's content (the fields that have no box as the draft has them) and that has been so for 300 ms (`armDelay`), so that a click on its way to something else when the card changed does not press. While live it has the orange ring and, beside it, "Yours: Send" (or Create, or Comment) in `accentInk`; when it cannot be pressed it is dimmed and says nothing about why. Nothing but agentd's word lights it |
| A press | `{"type": "press", "kind", "id", "fingerprint"}`, with the fingerprint agentd last gave for the content on the screen, once per draft until agentd answers: the button is dim from the press on (`pressOut`), so a second click sends nothing. It is the person's: nothing in the shell presses on a `card`, a `proposal` or a notice arriving |
| agentd's answer | `press_result`. `ok` makes the card say `sent`, with the receipt's line (else "Sent.") and a button "Open in `<service>`" when the receipt has a page. A refusal shows agentd's line under the button in red, until the person types in the box again or another card comes. An `unknown_outcome` makes the card say `unknown`, with agentd's words for it, and the button waits until the person ticks "I looked in `<service>`", then presses again with `"again": true` |
| A dropped connection | a press that was out when the socket dropped shows "I lost touch with the agent while that went, so I can't tell whether it did." under the button. When the connection is back the press is no longer waited on and agentd's state of the draft decides: a press that went is refused, one that did not may be made again |
| A notification's card | no draft: nothing goes to agentd as an edit or a press, the button is "Copy and open", quiet and with no ring, and it is live while the box has words |

`DraftBar` draws under the box the warnings (plain sentences on an amber box), what became of the press (the sending line, the receipt, the unknown outcome and its tick), agentd's `note`, the red line of a press agentd turned away, and then the button.

### The wallpaper

`shell/Wallpaper.qml` is a `Scope` that `shell.qml` makes once. For each screen it opens a window on `WlrLayer.Background` (namespace `bombadil-wallpaper`, `ExclusionMode.Ignore` so that it reaches the screen's edge under the bar's zone, an empty `mask` so that it takes no clicks) in the ground colour `Kit.Theme.bg`, and the picture fades in over it once (`Kit.Theme.slow`), so a slow, missing or broken picture leaves the plain ground. The standard picture is `share/wallpaper/bombadil.png`, found with `Quickshell.shellPath("../share/wallpaper/bombadil.png")`: `Qt.resolvedUrl("../share/...")` from `shell/` gives a dead end (`qrc:/qs-blackhole`), because Quickshell hides what lies outside the shell's folder. [Boot and the wallpaper](../design/boot-and-wallpaper.md) has the reasons, how the picture is drawn and the pictures.

| The `wallpaper` file in the config folder | The desk shows |
|---|---|
| missing, empty, or only `#` lines | the standard picture, undimmed |
| the last line that is not a `#` comment starts with `/`, `~/` or `file://` | that image, cropped to fill the screen (`PreserveAspectCrop`), with a layer of `Kit.Theme.bg` over it at opacity `dim` (0.6) |
| that line is anything else (an image written into the file is the usual case) | the standard picture, and a `console.warn` that names the file and never what is in it |
| the image will not load | the standard picture on that screen, undimmed; the next change of the choice tries again |

The config folder is `$BOMBADIL_CONFIG`, else `$XDG_CONFIG_HOME/bombadil`, else `~/.config/bombadil`, the folder `paths.config_dir` gives agentd. A `FileView` with `watchChanges` reloads the file when it changes. The skeleton ships the file with only comments in it, because a file that does not exist cannot be watched (the comment in `Wallpaper.qml`): with it there, a first path is noticed with no restart; where the file did not exist when the bar started, a first one needs the bar started again (`Super+Ctrl+Escape`). `dim` is 0.6 so that the muted text keeps a contrast of 4.5 on the quietest glass (`glassChip`) over a pure white picture; `tests/test_wallpaper.py` works that out from the tokens. `reducedMotion` takes the fade-in and the fade of the dim to 0.

### The desk's hosts

`shell.qml` hosts the desk and does not draw it: `DeskState` (fed by the same messages), a `DeskRails` per screen (inactive on all but the desk's screen), the two `DeskStrips` in the bar window, and `HyprCover`. The desk's screen is the one `desk.toml` names, else the first. `HyprCover` is the compositor-facing half: it asks Hyprland where the windows are and gives `desk.setWindows` the list. The Away card, which agentd's `away` message fills, has a strip chip like the other cards: `back · N things`, or `back · nothing new` for a count of zero (`DeskState._stripOf` and `_applyAway`, `shell/DeskState.qml:398-399, 913`). A tap on the card's title or the line under it, or on one of its rows, sends `{"type": "away", "op": "seen"}` and agentd takes the card away (`DeskState.awaySeen`, `DeskRail.qml`); a tap on the strip chip is not connected to anything (`DeskStrip` emits `clicked` and nothing listens). The card's own rules are in [desk.md](desk.md). The Widgets card is a desk surface too, but an item of the bar's column and not of a rail ([The Widgets card](#the-widgets-card)).

A card or a strip can be dragged (the drag, a drop and the desk's rules for it are in [desk.md](desk.md)), and that puts three things on the host. A drag reports screen coordinates, and a layer-shell window cannot ask where it sits, so each window says: `shell.qml` gives each `DeskStrips` an `origin` of `Qt.point(0, deskState.screenHeight - win.height)` (`shell.qml:475, 482`), the bar window's top-left, and `DeskRail` gives its `DeskDrag` handle the rail's own (`desk.railX(side)` and `T.railTop`). Every rail window stays up for as long as a drag lasts, an empty one too (`DeskRail.shown` follows `desk.dragging`), so the window the drag began in does not go. And `DeskStrips` draws the ghost chip of a card held over the row outside its own item, so it neither moves the pill nor widens what the bar's input mask holds.

| Part | What it does (`shell/HyprCover.qml`) |
|---|---|
| Refresh | `Hyprland.refreshMonitors()` and `refreshToplevels()`, then a `settle()` 40 ms later, and again 250 ms later for a slow answer |
| Events that refresh | `openwindow`, `closewindow`, `movewindow`, `movewindowv2`, `workspace`, `workspacev2`, `activespecial`, `activespecialv2`, `fullscreen`, `monitoradded`, `monitorremoved`, `focusedmon`, `changefloatingmode` |
| Polling | every 300 ms (`pollMs`) while any window is on the stage, because nothing reports a window being dragged |
| `settle()` | takes windows on the desk screen's active workspace or its shown special workspace, drops unmapped and hidden ones, and gives each `{x, y, w, h, kind, fullscreen}` in screen coordinates; `kind` is `panel` for a special workspace; `fullscreen` is true for Hyprland's states 2 and 3 |
| Startup | if the monitor's own answer has not arrived, it asks again every 100 ms, at most 20 times |
| Without Hyprland | does nothing; `qs ipc call desk cover` stands in |

### Theme, and why the shell starts through `bin/bombadil-shell`

The bar's files that draw (`shell.qml`, `StatusLine`, `QueueChips`, `SetupChips`, `FoundChips`, `NoticeChips`, `AiCard`, `WidgetsCard`, `PersonaCard`, `LineButton`, `Stone`, `CardHost`, `MessageFace`, `TaskFace`, `ListFace`, `DraftBar`, `CardBox`, `CardButton`, `CardScroll`, `ScrollThumb`, `Wallpaper`, `DevState`, `SessionChips` and `SessionPeek`) import the kit as `import Bombadil as Kit` and read `Kit.Theme.<token>`: colours (`glassPill`, `glassLine`, `glassChip`, `borderActive`, `accent`, `warn`, `bad`, `good`, `fg`, `muted`, `faint` and the rest), sizes (`pillHeight`, `radiusPill`, `chipHeight`, `pillMaxWidth`, `promptSize`, `lineSize`), type (`fontFamily`, `monoFamily`) and motion (`fast`, `normal` and `slow`, which read 0 under reduced motion, and `pulseLow`), the switch `reducedMotion` and `duration(ms)`, which is `ms` or 0 ([Motion](../MOTION.md)), and the `alpha()` helper the resting stone's fill uses. The desk's files (`DeskState`, `DeskCard`, `DeskRail`, `DeskRails`, `DeskStrip`, `DeskStrips`, `NowCard` and `RowsCard`) read `shell/DeskTheme.js` as `T` instead, a `.pragma library` script of plain values that cannot import a directory; `DeskState`, `DeskCard`, `DeskRail` and `DeskStrips` also import the kit, to wrap the durations they take from `T` in `Kit.Theme.duration(...)` and, in `DeskCard`, to hold the ring still under reduced motion. `tests/test_theme.py` keeps the 25 of its 33 values that have a token equal to that token; `railMargin`, `railTop`, `railBottom`, `cardGap`, `stripGap`, `foldMs`, `unfoldDelayMs` and `washMs` are layout and timing values with no token, and nothing compares them. `PillState`, `Draft`, `Notifications`, `HyprCover` and `DeskDrag` use no theme values.

Quickshell resolves a singleton only from the shell's own directory or from the import path, and a bare `quickshell -p shell/shell.qml` starts a bar whose colours are all undefined (`tests/test_theme.py:115`). So `bin/bombadil-shell` sets `QML2_IMPORT_PATH` to `<root>/share/qml` (keeping what was already there), finds `<root>` with `readlink -f` so the ISO's symlink in `/usr/local/bin` still reaches `/usr/share/bombadil`, and `exec`s `quickshell -p <root>/shell/shell.qml "$@"`. Every starter uses it: `bombadil-shell.service` (its `ExecStart` is `/usr/local/bin/bombadil-shell`, and it is reached from the Hyprland start hook and the rescue bind), `scripts/dev-session.sh` and `tests/desktop/driver.py`. A test fails if `hyprland.lua`, `scripts/dev-session.sh` or `tests/desktop/driver.py` calls `quickshell -p ...shell.qml` itself.

### The Hyprland config the ISO ships

`iso/airootfs/etc/skel/.config/hypr/hyprland.lua` is the session's whole Hyprland config. `bombadil-live.service` creates the session user with `useradd -m`, which fills the home folder from `/etc/skel` when it makes the home, and `bombadil-install` runs `cp -aT /etc/skel /home/user` in the installed system, which overwrites same-named files in a home that already exists. greetd starts `start-hyprland` as that user ([iso-and-install.md](iso-and-install.md)).

## Principles it keeps

- [One pill, three things to learn](../principles.md#stupidly-simple): the bar is the pill, the line and chips that appear on demand, and the keys are Super or Alt+Space, Esc and the word `undo`. The AI card is a click on the stone and the Widgets card is the word `widgets`, not controls on the bar. The trap is a second control surface (a button row, a menu, a settings page) in the bar window; look for the version that is a word in the pill.
- [Something true in 200 ms](../principles.md#something-true-in-200-ms): `PillState.submit` draws "On it" and the working face on the keypress and `agentd` confirms later; while the AI rests it draws the resting line at once and never "On it". The trap is waiting for `turn_start`, an animation or a reply before showing a state; every added state needs a line or a face that appears on the event that causes it.
- [Quiet at rest](../principles.md#quiet-at-rest): at rest the screen is the wallpaper, the pill and a still stone, and `StatusLine`'s timer runs only while a line shows and no picture holds it. While any coding session exists the chips row also sits above the pill, and only a working session's dot moves. The resting stone is still, and the resting line fades after 12 s. Every movement means one thing (roll, knock, hop, lean). Under reduced motion every movement in the bar and the desk has a still version: the stone's roll, knock, glow, hop and lean, the wallpaper's fade-in and dim, the fades and growth of the line, the picture, the AI card, the Widgets card, the name card and the chips, and the desk's folds, strips, pill width, wash and ring. A working dot's opacity pulse is the one movement that stays, the same with the switch on or off, as the stone's own still version is. The trap is a movement that means nothing or has no still version: animate with `Kit.Theme.fast`, `normal` and `slow` or `Kit.Theme.duration(ms)`, which read 0 under the switch; `tests/test_motion.py` fails an animation in `shell/` that ignores it ([Motion](../MOTION.md)).
- [Colour says who](../principles.md#colour-says-who): the bar's colours are `Kit.Theme` tokens, the desk's are `DeskTheme.js` values that `tests/test_theme.py` keeps equal to their tokens, and the same test fails a hex literal or a missing `font.family` in any `shell/*.qml`. The trap is using `accent` for decoration: orange means the machine acting, amber a step that touches the system, red a failure or a step that cannot be undone. A resting AI is grey and a plain step line, because nothing failed and nothing is acting; a red line for a limit would say the wrong thing.
- [Recovery never goes through the part that broke](../principles.md#recovery-without-the-broken-part) and [every piece degrades](../principles.md#degrade-and-recover): `Super+Escape` runs `bombadil stop`, which writes to agentd's socket directly, and `Super+Ctrl+Escape` restarts the bar's unit; neither goes through the model or through the shell's QML. systemd starts a dead bar or agentd again after about a second (`Restart=always`; [session-services.md](session-services.md)), so the key is for a bar that hangs and does not exit. The bar reconnects every 1500 ms with a fresh socket, says "Waiting for agentd…" while it waits, and hosts the picture card in a `Loader` so a card that cannot load or draw (`CardHost.qml`, a face or the kit's `Diagram` failing) costs the cards and never the bar; the notification server is hosted the same way, so a Quickshell without the service costs the notifications and nothing else. A wallpaper that is missing or will not load leaves the plain ground. The trap is moving a recovery action into a control that needs the shell to be alive, or a component that fails to load and takes the whole window with it; host anything that depends on a part that can be missing the way `cardHost` is. The `Bombadil` module is not such a part: every file of the bar imports it, which is why the bar starts through `bin/bombadil-shell`.
- [Nothing runs on its own that the person cannot see and stop](../principles.md#nothing-runs-unseen) and [only the person's own press reaches other people](../principles.md#the-persons-press-reaches-people): the resting state is on screen in the stone, the line, the empty field and the queue chips' labels, and its asks wait as chips the person can remove. The found chips only offer: nothing opens until a press, and a notice's chips act only on a press. The shell sends a `press` only from a card's Send, Create or Comment button, which is live only while agentd says the draft is ready and the box holds exactly what it has, and which the person presses (a draft the agent wrote is lit the same way and goes nowhere until then); Mail's Send is a button in the Mail window. The trap is opening, running or sending when a `found`, a `notice`, a `card` or a `proposal` arrives, or a button that does more than its label says.

## Extending it

There is no registry in the shell. `shell.qml` names each component by file name, and the test harness imports the directory, so a file in `shell/` is available by its name.

### Add a pill state, a line field or a face

1. Check that agentd already sends what you need ([agentd.md](agentd.md#events-the-shell-can-receive)). If not, add the event or the field there first.
2. In `shell/PillState.qml` add the property. Set it in `handle(ev)`: a top-level `ev.type` branch for a message, or a `case` in `switch (ev.kind)` for an event. Reset it where the others are reset (`turn_start` and `turn_end` clear `risk`, `command`, `because` and `after`).
3. If it changes the stone, edit the `face` binding. The first match wins, so the order is the precedence (`needs` outranks `working`; `tests/test_pill_qml.py::test_needs_you_outranks_a_running_turn` pins it). A face that only one screen shows is mapped in `shell.qml` as `listening` is (`face: win.summoned && pillState.face === "rest" ? "listening" : pillState.face`). The faces themselves are drawn in `shell/Stone.qml`; [the design system's recipe](../design-system/README.md#3-add-a-state-to-the-stone) lists the steps.
4. If it shows on the line, bind it in `shell/StatusLine.qml`: a `Text` with an `objectName`, `font.family: Kit.Theme.fontFamily` and a `visible` rule, or a change to `edge`.
5. Add a test to `tests/test_pill_qml.py` with `bar.send(kind=..., turn=...)`, `bar.call("method", ...)`, `bar.text("name")` and `bar.shown("name")`.

### Add a chip row

1. Copy `shell/QueueChips.qml`: a `RowLayout` with `required property var pill`, a `visible` rule on a `PillState` array (the row hides itself when the array is empty), and a `Repeater` whose delegate is a `Rectangle` of `Kit.Theme.chipHeight` with an `objectName`. Colours come from `glassChip` and `border`; each `Text` sets `font.family`.
2. In `PillState.qml` add the array property, fill it from the message, and add the method the click calls. Guard it with `if (_offline()) return` and send through `outgoing(...)`, as `unqueue` does. Call `handOff()` first if the click opens a window that needs the keyboard, as `setupAction` does.
3. In `shell.qml` add the row to the `ColumnLayout` (`id: column`) at the place it should sit, with `Layout.fillWidth: false`, `Layout.alignment: Qt.AlignHCenter` and a `Layout.maximumWidth`, as the other rows have. Add the row to the window's `mask`: a row outside the mask receives no clicks. For a row that hides itself, write the entry as `Region { item: <id>.visible ? <id> : null }`, as `personaCard`, `setupChips`, `foundChips`, `sessionChips`, `aiCard` and `widgetsCard` do (`shell/shell.qml:368-375`), because a hidden item keeps its last place in the mask. The other self-hiding rows are listed without that guard ([Known gaps](#known-gaps)), so do not copy their entries without checking, by clicking where the row was, that the window behind gets the click. Add its height to `exclusiveZone` only if tiled windows must be kept clear of it, as for the app chips and the session chips (the desk's rails stop above that zone too); the line, the queue chips and the picture are drawn over windows. A row inside an `Item`, as `sessionChips` is in `sessionRow`, gets the `Item`'s own `visible` from the state and not from the child's `visible`: a child is only visible while its parent is, so the row would never come back once hidden (the comment in `shell.qml`).
4. Add the row to `HARNESS` in `tests/test_pill_qml.py`, or the offscreen tests will not see it. A row that is driven by its own state object and not by `PillState`, as the session chips are by `DevState`, has its own `HARNESS` in `tests/test_sessions_qml.py`.

A setup chip needs no shell change: agentd returns `{id, label, style}` from its setup description (`style` of `big`, `primary`, or anything else for the quiet one) and handles the `id` in `setup_action` ([browser-and-signin.md](browser-and-signin.md)). The shell hands the keyboard off for every id except `cancel`, `resume` and `retry`.

### Add a card face

Another kind of card from a connection needs agentd's side first (`cards.py` must accept the type and the connection service must make it: [connect.md](connect.md)). The shell's side:

1. In `shell/PillState.qml` add the type to `cardKinds`. A card of any kind but `diagram` is taken only with a string `id`.
2. Write `shell/<Kind>Face.qml` as a `FocusScope` with `required property var pill`, `property var card` and `property int maxHeight`, and `Keys.onEscapePressed: face.pill.dismissCard()`. Draw every word with `textFormat: Text.PlainText`. Put rows or boxes in a `CardScroll` so that what must stay in view is outside what scrolls, take buttons from `CardButton` and boxes from `CardBox`, and send what a click does through `pill.cardAction(...)` or `pill.openThing(...)`, so that the face never writes to the socket.
3. A face with a box for a draft holds a `Draft` and a `DraftBar` as `MessageFace` and `TaskFace` do, passes `card` to the `Draft`, sets its `current` to what the boxes hold, writes into the boxes on its `write` signal and gives `CardBox.edited` to `draft.changed()`, `escaped` to `pill.dismissCard()` and `taken` to `pill.wantKeys()`. It has a `focusBox()` function that puts the keyboard in its first box: the bar calls it through `CardHost.focusBox()`.
4. In `shell/CardHost.qml` add a `Component` for the face and its line in the `sourceComponent` of the `face` loader, and, if the card needs less than the picture's width, its width in `preferredWidth`.
5. Cover it in `tests/test_connect_cards_qml.py`, which feeds a card made by `cards.accept` into a harness of the pill and the host and records what the bar would send.

### Add a keybind

A bind that needs only Hyprland is one line in `iso/airootfs/etc/skel/.config/hypr/hyprland.lua`, next to the panel keys: `hl.bind("SUPER + X", hl.dsp.exec_cmd("..."))`. The binds already taken are `SUPER` with `B`, `T`, `F`, `Q`, `Return`, `Escape` and `CTRL + Escape`, the two Super taps and `ALT + space`. There is no table of binds; this file is the table.

A bind that must reach the pill follows the path `summon` takes:

1. In `bin/bombadil` add a command that calls `send({"type": "<word>"})` (it returns at once, so a bind never hangs) and add its line to the docstring.
2. In `AgentD.handle` (`src/bombadil/agentd.py`) add a branch that broadcasts the message (`summon` is the `elif t == "summon"` branch at `:737-745`, which also passes optional `text` through `_pill_words` and passes a `tip` flag on; [agentd.md](agentd.md)), and add the message to the client-protocol list in the module docstring, where each socket message is documented (`summon` is at lines 17, 19 and 98).
3. In `PillState.handle` add `if (ev.type === "<word>") { <signal>(...); return }` and declare the signal with the arguments it carries (`signal summoned(string text)` is declared at `PillState.qml:12`; the branch that emits it is at `:409`).
4. In `shell.qml` connect it in the `PillState { }` block, as `onSummoned: text => root.summon(text)` is (`shell.qml:47`). The connection must take the signal's arguments.
5. Bind it in `hyprland.lua` with `hl.dsp.exec_cmd("bombadil <word>")`. A modifier tapped alone needs `{ release = true }`.
6. Cover it: add a broadcast test beside `test_key_binds_reach_the_bar` in `tests/test_agentd.py` (it is at `:528` and asserts the `summon` line at `:538`, and `:594` does the same inside another test; `test_a_summon_can_carry_words_for_the_pill` at `:544` is the model for a message with a field); extend the regex in `tests/test_iso_profile.py::test_the_pill_opens_from_super_and_from_alt_space` for the bind (it matches `bombadil pill` only); add a `PillState` test: connect the new signal in the `PillState { }` block of `HARNESS` and collect its arguments in a property, as `onSummoned` fills `summons` and `onHandOff` counts `handOffs` (`tests/test_pill_qml.py:39-49`), then assert on that property; `test_a_summon_can_carry_words_for_the_pill` at `:582` is the model, driven with `bar.send(type="<word>")`; and add a `keys` step to `iso/airootfs/usr/local/bin/bombadil-smoke`, which is where the binds are exercised in a real session.

The repository file is a skeleton: `useradd -m` copies it only when it makes the home, the installer copies it over the home it finds, and nothing copies it again, so a changed repository file does not reach a system that is already installed. `update-in-place`, the development tool that copies a checkout into a VM, leaves `~/.config/hypr/hyprland.lua` to be changed by hand (`scripts/vm-tools/update-in-place:14-16`).

### Add a shell component

1. Create `shell/<Name>.qml` with `import QtQuick` and `import Bombadil as Kit`. The alias must be exactly that: `tests/test_theme.py` rejects another. Take colours, sizes and motion from `Kit.Theme`, set `font.family: Kit.Theme.fontFamily` (`monoFamily` for commands) on every `Text` and `TextField`, and write no hex colour and no `"white"` or `"black"`; the test fails the file.
2. Keep logic in plain QtQuick (`PillState`, `DeskState` and `DevState` have no Quickshell type, so pytest loads them). Put `Quickshell.*` types (windows, `Hyprland`, `Socket`) in files the offscreen tests do not load, as `HyprCover.qml`, `DeskRails.qml` and `Wallpaper.qml` do; a file that wraps one Quickshell service can be loaded against a stand-in module instead, as `Notifications.qml` is (`tests/qml/quickshell_stub`, used by `tests/test_connect_cards_qml.py`).
3. If it can fail to load, host it through `Loader { Component.onCompleted: setSource("<Name>.qml", {...}) }` as `cardHost` does.
4. Place it in `shell.qml`: in the bar window's column (and add its `Region` to the mask), or as its own window per screen, as `DeskRails` and `Wallpaper` are, with a `WlrLayershell.namespace` and a `mask`.
5. Test it as `tests/test_pill_qml.py` tests the line: add it to `HARNESS` and give each thing a test looks for an `objectName`. A file that holds Quickshell types is checked as text, as `tests/test_wallpaper.py` does for `Wallpaper.qml`.
6. Nothing else registers it: `scripts/build-iso.sh` copies the `shell` folder whole to `/usr/share/bombadil/shell`.

### Add a status-line behaviour

- **An added field on a step.** `because` and `after` are the examples. agentd adds the field to the `status` event; `PillState.qml` reads it in `case "status"` and clears it in `turn_start` and `turn_end`; `StatusLine.qml` gets a `Text` with an `objectName` and a `visible` rule that includes `mode === "working"` and `flash === ""`. Test: send a `status` with the field and check `bar.shown("name")` (`test_resting_on_the_line_shows_why_and_a_marked_step_always_does` is the model).
- **Something that happens with time.** Use the 250 ms `Timer` in `StatusLine.qml` (`objectName: "lineTimer"`). Its `running` is `bar.shown`, with no notice alone on the line, less a finished line that a picture holds (`pictureStays`, mode not `working`, no flash), so a behaviour that must tick under a picture the person asked for needs that condition extended. How long a line stays is `PillState.fadeAfter`, set where the line appears together with `lineAt`; a local answer picks its time in the `local` case by `action` and `phase`. A test sets `fadeAfter` small and pumps events (`test_launcher_answers_replace_on_it_and_fade`; `test_a_picture_you_asked_for_keeps_its_line_so_the_picture_does_not_drop_when_the_line_goes` reads `lineTimer`'s `running`).
- **Something hover keeps alive.** Count it in `pill.hovers` the way `StatusLine` and `CardHost` do: add on enter, subtract on leave and in `Component.onDestruction`.
- **Something a hovered chip holds.** `FoundChips` shows the pattern for a control that is not the line: it counts itself once in `pill.hovers` while the pointer is on it and lets go the moment it hides or is destroyed, because a hidden item gets no hover-out.

### Add a notice, or a button under the resting line

Neither needs a change in the shell. A notice is agentd's: a service posts it to the stack in `src/bombadil/notices.py` with a line, a tone (`step`, `ask`, `done` or `error`), up to three chips of `{id, label, style}` and an optional time to live, and the handler of a chip is agentd's too ([mail.md](mail.md) for the one that exists). The shell draws whatever arrives and sends `notice_action` with the chip's id. A button under the resting line is a `setup` action: agentd adds it in `AgentD._describe` and handles its id in `setup_action`; add the id to the list in `PillState.setupAction` that does not hand the keyboard off (`cancel`, `resume`, `retry`) only if its click opens no window.

## Known gaps

- The socket path ignores `BOMBADIL_RUNTIME` and has no fallback for an unset `XDG_RUNTIME_DIR` (`shell/shell.qml:204`); agentd honours both (`src/bombadil/paths.py:14-20`: `runtime_dir` takes `BOMBADIL_RUNTIME`, else `XDG_RUNTIME_DIR` with a `/run/user/<uid>` fallback, and `socket_path` takes `BOMBADIL_SOCKET`). With only `BOMBADIL_RUNTIME` set, the two sides look in different places.
- The launcher mirror is smaller than the launcher. `PillState._verbs` has eight verbs (`keep` is the last) and does not drop "the" (`shell/PillState.qml:971`); `launcher.py` accepts `run`, `bring up`, `go to`, `switch to`, `exit`, `kill` and `put away` as well and drops "the" (`src/bombadil/launcher.py:148-150, 201-206`), so `keep the machine` gets no hint. "open the browser" opens the browser but shows no `↵ Browser` hint and no completion. The words `pause` and `resume`, the picture phrases ("how am I connected"), the machine questions, the volume words (`volume up`, `volume down`, `mute` and `unmute`: `UTILITY_COMMANDS`, left out of `entries()` by `NO_COMPLETE`) and the model words (`use opus` and `use sonnet`: `MODEL_WORDS`, which `entries()` never lists) are in `launcher.py` and not in the `entries` message, so they get no hint and no completion either. The words for coding sessions are mirrored in part: `Dev.names()` lists each project, `<tool> <project>` and each named session's role (`src/bombadil/dev.py:261-274`), while `<tool> <project> <role>`, `<role> on <project>`, `end <role>` and the list words (`sessions`, `what's running`) are in `launcher._dev_match` only (`src/bombadil/launcher.py:180-182, 248-289`), and `PillState._verbs` has no `end`, so those get no hint and no completion. The word `widgets` is mirrored bare (a command entry, so `widgets` shows `↵ Widgets`), but `show widgets`, `open my widgets` and the other forms of `CORE_COMMANDS["widgets"]` are launcher words only, because the mirror skips a command after a verb. The words for connections are mirrored in part as well: `entries()` lists `messages` and `connections` (`CONNECT_ENTRIES`), while `slack`, `unread`, `connected`, the longer questions of `CONNECT_VIEWS` and `connect <service>` are in `launcher.py` only (`_connect_action`, `src/bombadil/launcher.py:423`), so those get no hint and no completion.
- The 64 in the bar's `exclusiveZone` (`shell/shell.qml:361`) is a literal, not derived from `Theme.pillHeight` (52) and the 12 px margin; the desk's `rowZone` (`shell/DeskState.qml:192`) and `deskZone`'s fallback (`shell/shell.qml:142`) repeat it as a default. The rails follow the bar's zone when a bar is on the desk's screen, so a change of the pill's height needs only the literal in `exclusiveZone` and the two fallbacks changed.
- A local error line that has no turn does not set `fadeAfter` (`shell/PillState.qml:471`), so it stays as long as the previous line's setting, 15 s after an undo line.
- `BOMBADIL_REDUCE_MOTION` is read once, when the shell starts, and nothing in the repository sets it (`shell/shell.qml:36`; `hyprland.lua`, the units and the installer do not), so reduced motion is off in every session of the image until someone sets the variable and starts the shell again. Hyprland's own animations (windows, special workspaces and fades, set in `hyprland.lua`) do not read it, so a window or a drawer still slides in ([Motion](../MOTION.md)).
- A click on a session's dot and Tab in an empty pill send through `root.write`, which does nothing while the socket is down, and `DevState.open` and `DevState.next` do not check (`shell/DevState.qml:104-111`, `shell/shell.qml:234-236`), so while disconnected they do nothing and say nothing. The pill's own methods answer such a click with "Not connected to the agent yet." (the Handling paragraph of [How it works](#how-it-works)).
- Designed in the briefs and absent from `shell/`: the "this" chip, example chips and the first-day hint (the [Tips brief](../design/tips-and-desk-defaults-brief.md) keeps the first-day line and is design only), a mark on the stone for a waiting notice (`Stone.qml` has no such face; a notice shows only as the line), the "Use Codex until 15:00" button and the warning line before a limit (poor man switch pieces 3 and 4, [poor-man-switch.md](poor-man-switch.md)), battery and music beside the clock, drop and paste onto the pill, voice input (push to talk). The pill's row has the stone, the field, the hint and the clock. The shell draws no desktop notification pop-up of its own: a notification reaches the person as agentd's notice, which `NoticeChips` draws ([the notification server](#the-notification-server)).
- Only the Hyprland start hook starts the units that bring the bar and agentd back (`hyprland.lua:9-10`; `bombadil-agentd.service` and `bombadil-shell.service` have no `[Install]` section, and `default.target.wants` holds only the brain's, Mail's and the browser service's units). `scripts/dev-session.sh` and `tests/desktop/driver.py` run `agentd` and the bar directly, so in a dev session and in the desktop test nothing restarts either when it dies. The units set no watchdog, so systemd restarts a bar that exits and not one that hangs; `Super+Ctrl+Escape` restarts that one (`iso/airootfs/etc/systemd/user/bombadil-shell.service`).
- The two `IdleMonitor` blocks (`shell/shell.qml:58-70`) are pinned as text only (`tests/test_welcome_qml.py`): no test or smoke check shows that Hyprland delivers idle events to them, so the away signal and the welcome's first touch have never run outside an offscreen harness.
- `cardHost`, `statusLine`, `chips` (the queue) and `appChips` hide themselves, yet their entries in the input mask have no `visible` guard (`shell/shell.qml:364-379`), while `personaCard`, `setupChips`, `foundChips`, `sessionChips`, `aiCard` and `widgetsCard` have one because a hidden item keeps its last place (`:368-375`). Whether the unguarded rows leave a dead input area above the pill was not tested: no test loads `shell.qml`'s mask.
- `openThing` hands the keyboard off only for a box that names a turn (`shell/PillState.qml:374-376`). For a file, a service or a package the drawer is opened by agentd and the pill keeps the keyboard if it held it. No test covers a click in a picture while the pill is summoned.
- A `wallpaper` file that does not exist when the bar starts is not watched, so on a home without the skeleton's copy (a system made before the skeleton shipped it) a first file needs the bar started again (the comment in `shell/Wallpaper.qml:13-17`). The desktop test starts from the shipped file and does not try the missing one.
